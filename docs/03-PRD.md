## 0. 已确定的产品前提（不再作为开放问题）

| 维度 | 用户答案 | 对产品的影响 |
|---|---|---|
| **饲料类型** | **浮性膨化料** | 「被吃掉 vs 沉底」风险**大部分解除**；但**新增「颗粒漂散出视野被误计为吃掉」风险**，且浮料吸水软化后长时间仍会缓沉 → 仍需边缘穿越判定与残留损失校正 |
| **拍摄场景** | **户外池塘 / 网箱** | 非实验室环境：**水面波浪、反光、光照随时间漂移、机位大概率斜拍**。产品必须内置拍摄规范引导与质量告警，**且行为类指标的可靠性显著低于实验室场景** |
| **数据基础** | 有历史视频，愿意标注少量帧 | 模型微调路线可行，需「标定向导」引导用户标 20–50 帧 |
| **主要用途** | **科研：诱食剂/饲料对比实验，结果进论文** | **硬约束**：可复现、可导出统计检验、支持分组对比与盲法编号、可回答审稿人质询 |

## 1. 产品目标

### 1.1 一句话定位

> **一套面向水产科研的「鱼类摄食行为视频测量」工具：把"投喂—吃完"的全过程录像，转换成可复现、可统计、可写进论文的量化指标，让诱食剂与饲料配方的效果对比从"凭经验看"变成"用数据说"。**

### 1.2 三条量化目标

| # | 目标 | 量化指标 | 当前基线 |
|---|---|---|---|
| **G1** | **测得准**：饲料消耗过程的量化误差可控且**已知** | 在完成标定与真值对照的场景下，**颗粒计数平均绝对误差（MAE）≤ 10%**；**且每一次分析都给出本场景的实测误差或明确标注"无法测量"** | 目前无任何自动化手段，只能人工观察 |
| **G2** | **分得出**：能检出诱食剂/饲料配方之间的真实差异 | 对存在真实差异的处理组，**统计检验检出率（power）≥ 80%（α=0.05）**，在用户给出的重复次数下；**并输出效应量与置信区间** | 人工评分主观、不可复现 |
| **G3** | **可复现、可答辩**：结果能经得起审稿人质询 | 任一次分析结果均可在**同机器 5 分钟内完整重跑**，且导出的**参数包 + 版本 + 模型指纹**足以让他人在同类环境下复现同一组数 | 无 |

> 🔴 **G1 里"或明确标注无法测量"这句与前面同等重要。** 本工具的任何一个指标都没有先验的准确度保证；**当我们无法测出误差时，必须如实说"无法测量"，而不是给一个好看的数字。** 这是本产品的核心设计原则（详见 §6.1）。

## 2. 目标用户与核心场景

### 2.1 用户画像

| 角色 | 描述 | 核心诉求 |
|---|---|---|
| **主用户：水产科研人员**（饲料/营养/养殖方向，硕士/博士/企业研发） | 手上有成套的养殖视频，做过或正在做诱食剂对比实验 | 要**能写进论文**的定量结果；要能回答审稿人"你怎么保证数据可靠" |
| **次要用户：养殖一线技术员** | 负责投喂管理 | 想知道"这批料鱼爱吃吗、多久吃完"，用于投喂决策 |

### 2.2 主场景（详细描述）

> **一位水产科研人员，手上有 12 段"投喂浮性膨化料 → 吃完"的户外池塘视频，分为对照组（基础饲料）与实验组（添加 0.5% 诱食剂），每组 6 次重复（分 3 天、每天 2 次，交叉设计）。**
>
> 他需要：
> 1. 一次性导入 12 段视频，按「对照组 / 实验组」打标签，并给每段编盲法编号（分析时不知道哪段是哪组）；
> 2. 用同一个 ROI 与标定参数处理全部视频（**参数锁定**，否则不可比）；
> 3. 批量跑完分析，看到进度；
> 4. 得到每段的：**剩余颗粒数—时间曲线、T50 / T90、峰值消耗速率、残留率、首次摄食潜伏期、投喂区鱼数占比 RP、活跃度曲线**；
> 5. 在少数几段上人工修正颗粒计数（承认检测有误差），修正后下游指标自动重算，且**修正量被记录**；
> 6. 得到两组的**统计比较结果**：t 检验或 Mann–Whitney、p 值、**效应量 Cohen's d、95% 置信区间**；
> 7. 一键导出：逐帧时序 CSV、汇总指标 Excel（多 sheet）、图表 PNG/PDF、**以及一段可直接粘进论文"材料与方法"的方法学描述**；
> 8. 三个月后审稿人要求补充数据，他能导入当时的参数包，**完整复现当时的结果**。

### 2.3 场景对设计的三条硬要求

| 场景特征 | 硬要求 |
|---|---|
| **户外池塘（波浪 + 光照漂移 + 反光）** | 🔴 **全画面帧差类指标（CVFAI）在户外不是"精度下降"，而是"信噪比可能 <1、前提即不成立"**——波浪是持续背景运动且**风力随时间变化**，所以**投喂前基线期不能代表全程噪声地板**，我们那套"基线 μ±3σ"判据在户外失效。<br>① 必须做**参考区逐帧噪声扣除 + 空间异质性判别**（P0-FR-13）；<br>② **主结论必须建立在颗粒曲线（A 组）上**，行为类指标仅作支持性证据；<br>③ 质量分超阈值醒目告警 |
| **浮性料（三种消失风险）** | 颗粒消失有**三种**：漂出 ROI 边界（**可判定**）／**漂进反光区后消失（无法区分，记为 unknown，不猜测）**／**被波浪短暂淹没后重现（需"容忍短暂消失 ≥N 帧"）**。必须有边界穿越 + unknown 不猜测 + 短暂消失容忍（P0-FR-14） |
| **斜拍** | 需 4 点透视标定（P0-FR-07）；🔴 **且必须向用户说明能力边界：单应性变换只解决"近远尺度不一致"，❌ 不解决斜拍造成的物理遮挡——投影变换还原不了被遮住的信息** |
| **结果进论文** | ① 统计检验完整输出（p + 效应量 + CI + 检验方法 + 样本量 + **重复结构**）；② 盲法编号；③ 可复现参数包；④ 人工修正留痕；⑤ **必须处理伪重复**（P0-FR-37） |

## 4. 需求池

> **需求 ID 规则**：`P0-FR-xx` 功能需求 ／ `P0-NFR-xx` 非功能需求
> **验收标准必须可判定**，避免"良好""流畅"这类无法验收的描述。

### 4.1 P0 —— 第一版必须交付

#### 4.1.1 项目、数据与采集规范

| ID | 需求描述 | 验收标准 |
|---|---|---|
| **P0-FR-01** | **项目管理**：创建/打开项目，批量导入视频，按组标签（对照/实验/剂量）管理 | 支持一次导入 ≥20 段视频；可为每段设置组标签与盲法编号；项目配置持久化 |
| **P0-FR-02** | **盲法编号**：分析阶段隐藏分组归属，揭盲需显式操作且留痕 | 分析界面不显示组标签；揭盲操作写入运行日志；导出可选择性包含/排除分组信息 |
| **P0-FR-03** | **拍摄规范自检清单**：内置可勾选清单，逐条说明"为什么"与"做不到会怎样" | 至少覆盖 8 条：相机固定、一镜到底、非慢动作/延时、含投喂前 ≥30 s 空镜头、画面内有尺寸参照物、避免过度反光、原始码流不二次压缩、光照稳定。**未勾选的条目在报告中列为"已知采集偏差"** |
| **P0-FR-04** | **实验元数据表单**：结构化填写，✅ 必填字段强制校验 | 必填：鱼种、池中总鱼数、平均体长、投喂量(g)、单颗均重(mg)、饲料类型(浮性/缓沉/沉性)。选填：平均体重、水温、溶氧、pH、养殖密度、禁食时长、养殖模式。**任一必填为空则不允许启动分析**；全部元数据写入导出报告表头 |
| **P0-FR-05** | **参数锁定**：项目级统一配置（ROI、标定、阈值、模型），所有视频复用 | 修改项目级参数时提示"将影响 N 段已分析视频，需重新运行"；导出包含完整参数 |

#### 4.1.2 区域、标定与时间基准

| ID | 需求描述 | 验收标准 |
|---|---|---|
| **P0-FR-06** | **ROI 框定**：在首帧上绘制投喂区、参考区、排除区 | 支持多边形绘制与模板复用；投喂区用于颗粒计数与鱼数统计；排除区（反光/池外）在分析中被掩膜剔除；ROI 随项目保存 |
| **P0-FR-07** | **透视标定（户外斜拍必需）**：用已知尺寸的投饵框/参照物做标定 | 支持 4 点透视标定，输出像素—物理单位换算；**未标定时所有物理量纲（mm/BL）指标自动降级为像素口径并标注"不可跨视频比较"** |
| **P0-FR-08** | **投喂起点 t0 打点**：手动打点 + 自动检测建议，且必须选择定义 | 提供三选一定义（投饵器启动 / 饲料离开投饵器 / 饲料出现在画面），默认"饲料出现在画面"；**t0 定义与来源（手动/自动）均写入参数包**；手动与自动偏差 >1 s 时告警 |
| **P0-FR-09** | **基线期设定**：标记投喂前 ≥30 s 作为基线 | 基线不足 30 s 时，所有相对基线指标（RP、归一化活跃度）**强制关闭并明示原因**；基线窗口长度可调，默认 60 s |
| **P0-FR-10** | **时间轴完整性自检**：检测时间轴异常 | 自动检测：① 时间戳非单调（多段拼接）→ 告警并拒绝输出断裂后的时间指标；② 标称时长与实际解码时长偏差 >2% → 告警"疑似可变帧率"；③ 用户声明使用慢动作/延时 → 强制标注 |

#### 4.1.3 检测、分析与质量

| ID | 需求描述 | 验收标准 |
|---|---|---|
| **P0-FR-11** | **标定向导（混合标注策略）**：引导用户标注 20–50 帧<br>⭐ **颗粒用点标注，鱼用框标注** | 向导自动挑选覆盖不同阶段的代表性帧（投喂后 5 s / 30 s / 60 s / 接近吃完 / 聚集最紧时刻）。<br>🔴 **颗粒必须用点标注**：20–50 帧 × 每帧上百颗粒 = 2,000–5,000 个目标，**bbox 标注需 3–6 小时，会直接劝退用户**；改为点标注后**按 `A_single` 半径自动生成训练框**，降至 **40–80 分钟**，且与面积积分法共用同一标定值（一致性好）<br>**鱼用框标注**（数量小，几十个；且跟踪器需要框）<br>支持导出/导入标注；标注工具建议 Label Studio（点标注配置灵活、pip 安装免 Docker） |
| **P0-FR-11b** | **颗粒动力学预标定**：`scripts/00_calibrate_pellet_dynamics.py`，输入"无鱼纯饲料"视频 | ⭐ **主产出改为 `A_single(t)`（单颗平均投影面积，含时间校正）** —— 浮性料场景下它比 `v_sink_max` 重要得多（面积积分计数的必需标定值）<br>`v_sink_max` **保留但降级为可选**（浮料吸水软化后长时间仍会缓沉）<br>两者均从**同一段**"无鱼纯饲料"视频测得，**不增加用户负担** |
| **P0-FR-12** | **批量分析与进度**：批量运行并展示进度 | 逐段显示进度与当前阶段；支持中断与续跑；失败的视频单独标记不影响其他视频 |
| **P0-FR-13** | **活跃度的户外噪声抑制**（两步，均为 P0）<br>⑬‑a **参考区逐帧扣除**：`M_corrected(t) = M(投喂区,t) − α·M(参考区,t)`，**α 由基线期回归得到**（不得拍脑袋）<br>⑬‑b ⭐ **空间异质性判别**：把投喂区网格化（默认 16×16）计算帧差，用**峰度 / 基尼系数 / 前 5% 格子能量占比**判别 | ⑬‑a：参考区与投喂区处于相同水面条件、无鱼无料；**无参考区时明确标注"未做噪声扣除，户外波浪可能虚增活跃度"**<br>⑬‑b：**原理是"波浪→空间均匀（整片水面一起起伏，抬高所有格子但不改变分布形状）；抢食→空间局部集中（改变分布形状）"**，故这些量对全局性波浪不敏感。纯 OpenCV，成本极低<br>⚠️ **能力边界须写明：空间异质性可区分"波浪 vs 局部活动"，但区分不了"抢食 vs 水花"**——后者对本产品可接受（均属摄食相关活动） |
| **P0-FR-14** | **非摄食损失三分类（浮性料关键）**：颗粒的消失必须分三类，不得合并 | 输出 `n_eaten`（判定为摄食）／`n_drifted`（**轨迹穿越 ROI 边界或排除区** → 判定为漂出）／`n_unknown`（**漂进反光区后消失等无法判定情形**）。<br>🔴 **`n_unknown` 一律记为 unknown，严禁猜测归类**（延续"unknown 不得猜测"纪律）<br>⚠️ **需"容忍短暂消失 ≥N 帧"逻辑**（N 可配置）：被波浪短暂淹没后会重现，**否则误计为消耗**<br>`n_drifted + n_unknown` 合计占比 >15% 时，**T90 与残留率自动标注"含非摄食损失"，且必须与漂出颗粒数并列展示** |
| **P0-FR-14b** | ⭐ **面积积分计数法（针对 N₀ 系统性低估）**：`N_area = 颗粒区前景总面积 / A_single` | 与逐个检测**并行**输出两条 `N_p(t)` 曲线供交叉校验。<br>**原理：密集粘连时逐个检测必然漏检，但面积积分对部分遮挡不敏感；而 t≈0 颗粒最密集处正是它最适用的时刻**——恰好针对难点 #9<br>⚠️ **`A_single` 须按时间校正**：浮性料吸水膨胀后投影面积缓慢增大，不校正会导致**后期颗粒数被系统性低估**。由"无鱼纯饲料"视频标定 `A_single(t)` 曲线<br>两条曲线偏差 >20% 时告警 |
| **P0-FR-15** | **质量分展示与告警** | 每段视频输出 `Q_det`（颗粒检测置信度）、`Q_track`（可追踪个体比例）、`Q_interf`（反光/波浪污染帧占比）；**任一超阈值时界面醒目告警，并在报告中标注"该样本建议人工复核"** |

| **P0-FR-36** | **flag 术语表** | 每个对外暴露的质量标记配一句中文解释 + **建议动作**（如"本值可能含漂出损失，请勿单独用于判断摄食速度，建议改用残留率 RR"）；术语表同时出现在报告与独立 CSV |
| **P0-FR-37** | 🔴 **重复结构声明与伪重复处理**（科研必需，架构师 v14 指出） | 用户**必须**声明每段视频属于**哪个池塘/网箱**、哪一天、第几次投喂。<br>⭐ **默认把"池塘/网箱"作为随机效应（混合效应模型），不把同一池塘的多次投喂当作独立样本**<br>🔴 **原理：同一池塘重复投喂 5 次 ≠ n=5**，独立样本是**池塘/网箱数**；把重复测量当独立样本会**严重高估显著性（伪重复）**<br>若**只有一个池塘** → 报告中必须标注"**无独立重复，本结果仅具描述性，不可做统计推断**"<br>导出时随统计量一并给出重复结构说明 |
| **P0-FR-38** | ⭐ **浮动投喂框（拍摄条件要求，非可选项）** | 产品须**明确要求**用户在投喂点布设固定尺寸的浮动投喂框（PVC 管或泡沫浮框，成本几十元），并在拍摄规范清单中作为**强建议项**。<br>**一个改动解决四个问题**：① 漂出率大幅下降（"漂出 vs 吃掉"的判定范围从整池缩到框边界）；② `pellet_zone` 直接由框定义，无需人工估计；③ **框的四个角就是单应性变换的四个标定点——标定与 ROI 一次完成**；④ 框内面积已知，可反推投喂量使颗粒重叠度可接受<br>🔴 **有框 → 精度落在"典型档"（±10–20%）；无框 → 落在"较差档"（±25–40%）**——这是决定精度档位的关键因素，不是锦上添花<br>未布设时在报告中标注"未使用投喂框，漂出风险高" |

## 6. 明确不做的事（Non-goals）

> **本节是防止需求蔓延与误用的护栏。以下条目不是"以后会做"，而是"原理上不做"或"第一版明确不做"。**

### 6.1 🔴 原理上不可得的指标（**单段投喂视频无法产出，任何"估算"都是误导**）

| 不做的指标 | 为什么不做 |
|---|---|
| **FCR 饲料系数 / 饲料转化率** | 需要**跨天**的累计投喂量与鱼体增重。单段视频只有一次投喂、没有体重变化 |
| **SGR 特定生长率** | 需要初末体重与养殖天数（**天**尺度）。单段视频是**分钟**尺度 |
| **WGR 增重率 / PER 蛋白质效率** | 同上，需要跨周期称重与摄食量 |
| **CF 肥满度 / HSI 肝体比 / VSI 脏体比** | 需要捕捞、麻醉、解剖测量 |
| **SR 成活率** | 需要跨周期计数 |
| **重量法摄食率 FR（%体重/d）** | 需要干重摄食量与养殖天数 |

> 📌 **替代做法**：当用户需要这些指标时，产品应**提示他需要补测什么**（初末体重、累计投喂量、养殖天数），而不是自己编一个数。**宁可少给，不可给错。**

### 6.2 🔴 技术上不可靠、第一版明确不做

| 不做的事 | 为什么不做 |
|---|---|
| **咬食 / 吐食次数** | 需要个体口部清晰可见的高分辨率特写；群体俯拍/斜拍场景下无法可靠识别 |
| **摆尾频率、鱼头转角等精细姿态指标** | 需要 ≥60 fps 且个体清晰；户外池塘场景不满足 |
| **个体级指标在中高密度场景** | 鱼体重叠导致跟踪不可靠；**此时主动关闭并说明原因，而不是硬凑数** |
| **"摄食强度等级"作为计量结论** | 等级（强/中/弱/无）是定性输出，**不可跨批比较**；仅作辅助可视化并明确标注 |
| **跨视频的绝对数值直接比较（未锁参数时）** | 参数不一致时结果不可比；系统应拒绝或告警，不支持强行比较 |
| **实时/在线处理** | 用户场景是离线分析已录好的视频；离线可使用更重的模型与更充分的后处理 |

### 6.3 🔴 产品承诺上不做

| 不做的事 | 为什么不做 |
|---|---|
| **不给"可信度 / 置信度评分"这类摘要标量** | 它把 `status` + `flags` + `quality` 三个结构化字段压缩成一个数，**信息必然丢失且用户会过度信任它**。要筛选就筛 `blocking_flags` 这类结构化字段 |
| **不在没有真值对照时声称精度** | 本工具没有任何指标被独立验证过。**未测出误差 ≠ 没有误差，更不等于"很准"** |
| **不在未校正漂出/沉降损失时称"已校正"** | 同上 |
| **不提供"用户确认后强制比较"的绕过开关** | 会诱导用户绕过保护，而这类偏差不可察觉。**改为始终提供"重跑对齐"这条低成本出路** |

## 7. 待确认问题

> 以下 5 条会实质影响范围或设计，**需要用户拍板**。

| # | 问题 | 为什么重要 | 若未答的默认处理 |
|---|---|---|---|
| **Q1** | **对比实验是「两组对照 vs 实验」，还是「同一诱食剂设 ≥3 个剂量梯度」？** | **决定统计模块**：两组用 t 检验/Mann–Whitney；剂量梯度需**趋势检验与回归求最适浓度**——是结构差异而非参数差异，事后改代价大 | 按两组对照实现；剂量梯度留到 P1 |
| **Q2** | **能否在投喂点布设固定尺寸的投饵框（或浮性围栏）与尺寸参照物？** | ① **投饵框是控制"颗粒漂散出视野被误计为吃掉"的唯一有效手段**（浮性料的核心风险）；② 参照物是透视标定的前提（户外斜拍必需） | 无投饵框 → 漂出率必然偏高，T90/残留率将长期标注"含非摄食损失"；无参照物 → 物理量纲指标降级为像素口径 |
| **Q3** | **机位是固定的还是手持？俯拍还是斜拍？如果是斜拍，能否提供画面内已知尺寸的平面参照物？** | 决定是否需要透视标定（单应性），以及背景建模是否可用（手持则不可用） | 按"固定 + 斜拍 + 可布设参照物"设计；若实为手持，第 0 层规则法需重新评估 |
| **Q4** | **每个处理组计划做几次重复？整个实验周期多长？** | 行为学数据变异大，**重复次数决定统计功效**；<6 次时即使有真实差异也可能检不出（假阴性） | 按 ≥6 次设计；实际更少时报告明确标注"统计功效不足，结论仅供参考" |
| **Q5** | **是否愿意提供一次人工计数对照（对 1 段视频的 5–10 帧数出颗粒数与鱼数）？** | **这是把"未检出缺陷"升级为"实测误差 = X%"的唯一途径**，也是我们敢对精度做任何声明的前提。**成本极低，但必须在正式采集数据前安排** | 无真值 → 所有指标只能标注"未检出已知缺陷"，**无法给出任何精度数字**；鱼数误差完全不可知（而 RP 等核心指标建立在鱼数上） |

## 附录 B：本 PRD 遵循的六条设计原则

1. **不得给出无法兑现的承诺** —— 结论若依赖我们没有的机制（真值对照、人工核验），就不能说。
2. **边界处不得使用有语义的默认值** —— 不用 0 冒充空、不硬编码物理参数、误差低于噪声下限时不得报"误差≈0"。
3. **影响跨批次可比性的决策必须版本化并参与比较校验** —— 判定：它变了会让两次运行不可比，就必须进参数包并被校验。
4. **数值必须与其适用边界一同传递，边界不得只留在文档里** —— 判定：把数值单独发给一个没有上下文的人，他能否判断该不该用？
5. **schema 中每一列必须声明消费方与消费时机** —— 没有消费方的列不进 schema。
6. **禁止"可信度摘要标量"** —— 需要"能不能用"的筛选器时，用结构化字段，不要造一个数。
