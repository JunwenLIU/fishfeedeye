# 04 · 指标输入契约（Metrics Input Contract）

> 编写人：许清楚（PM）｜日期：2026-08-29
> 用途：**`metrics/` 层与 `pipeline/` 层之间的接口契约**，供工程师照此实现与写单测；`capability.py` 的降级逻辑直接由本文"失效条件"字段驱动。
> 配套文档：`01-research-fish-feeding-behavior.md`（指标学术定义与来源）、`02-research-open-source-stack.md`（技术栈与目录结构）
> 约定：本文只定义**契约**（输入 / 输出 / 质量分 / 失效条件），不规定实现。

---

## 0. 设计原则（请先读这四条）

1. **没有质量分的指标不允许输出。** 每个指标的输出结构里 `quality` 是**必填字段**，不是可选。
2. **失效条件必须是 `capability.py` 可求值的布尔表达式。** 本文所有"失效条件"都已写成可判定的形式（阈值常量见 §5）。
3. **右删失（censored）≠ 失败。** 观察窗内没发生的事件（如 T50 没到），输出 `">窗长"` 并打 `censored=True`，**不要输出 0 或 NaN 冒充**。
4. **不输出 = 正确行为。** 指标被关闭时，报告中应显式列出"本指标因 X 原因未输出"，而不是静默省略。

## 1. 通用输入数据结构（pipeline → metrics）

`pipeline/` 必须向 `metrics/` 提供以下标准结构。**字段缺失用 `None`，不得用 0 填充**（0 是有意义的数值）。

```python
@dataclass
class FrameContext:
    t: float              # 秒，相对投喂起点 t0。t < 0 表示基线期（投喂前）
    frame_idx: int
    width: int; height: int
    fps_source: float     # 源视频帧率
    px_per_mm: float|None # 标定尺度；未标定 = None
    in_baseline: bool     # 是否属于基线期

@dataclass
class PelletDetections:          # 颗粒
    centroid: np.ndarray   # (N,2) float, 像素
    bbox: np.ndarray       # (N,4)
    conf: np.ndarray       # (N,)
    area_px: np.ndarray    # (N,)
    track_id: np.ndarray|None   # (N,) 轻量关联，可为 None

@dataclass
class FishDetections:            # 鱼体
    bbox: np.ndarray       # (M,4)
    conf: np.ndarray       # (M,)
    mask: np.ndarray|None  # (M,H,W) 可选分割
    track_id: np.ndarray|None
    heading: float|None    # (M,) 弧度，可选

@dataclass
class Tracks:                    # 累积轨迹（跨帧）
    track_id: list[int]
    t: list[np.ndarray]     # 每条轨迹的时间戳数组
    xy: list[np.ndarray]    # 每条轨迹的质心数组 (k,2)
    heading: list[np.ndarray]|None
    n_frames_alive: list[int]

@dataclass
class ROI:
    arena: Polygon          # 有效水域（必填）
    feed_zone: Polygon|None # 投喂区（RP / 停留时长 依赖）
    feed_center: tuple|None # 投喂点 R
    pellet_zone: Polygon|None  # 颗粒计数区（通常 = 投喂框内）
    exclusion: list[Polygon]   # 排除区：反光 / 遮挡 / 池外 / 设备
    bottom_band: Polygon|None  # 底部带（用于判定颗粒沉降离开）

@dataclass
class BaselineStats:        # 基线期（t<0）统计；基线缺失则整个对象为 None
    n_frames: int
    duration_s: float
    fish_count_mean: float; fish_count_std: float
    n_fz_mean: float;       n_fz_std: float        # 投喂区鱼数基线
    activity_mean: float;   activity_std: float    # 帧差能量基线
    flow_mean: float;       flow_std: float        # 光流幅值基线
    annd_mean: float;       annd_std: float
    pellet_count_mean: float                       # 应恒为 0，用于校验投喂起点

@dataclass
class RunMeta:              # 用户元数据（缺项 = None）
    species: str|None
    n_fish_total: int|None
    body_length_mm: float|None
    body_weight_g: float|None
    feed_mass_g: float|None          # 投喂量
    pellet_mass_mg: float|None       # 单颗均重
    pellet_type: str|None            # 'floating' | 'sinking' | 'slow-sinking'
    water_temp_c: float|None
```

### 时间基准约定（**最关键的一条**）

- **`t0`（投喂起点）是所有时间指标的基准。** pipeline 必须提供 `t0`，来源优先级：用户手动打点 > 自动检测（颗粒数首次 >0 且持续）。
- **基线期 = `[t0 - baseline_window, t0)`**，默认窗口 60 s，最短 30 s。**基线帧数不足 → `BaselineStats = None` → 所有相对基线指标强制关闭。**

### 🔴 时间基准的两类风险（**缺一不可，两类都会静默污染全部时间指标**）

#### ① 时间轴本身（技术层，架构师 v8 指出）

> 手机/运动相机录的视频常是 **VFR（可变帧率）**，容器的 `CAP_PROP_FPS` 只是标称平均值，**与逐帧实际时间戳不符**。若按标称 FPS 推算 `t_seconds`，**时间轴会漂移**；
> 而 **T50 / T90 / RR 观察窗 / 摄食起止时刻 / 所有速率指标全部建立在时间轴上——错了不报错，且事后无从察觉。**

> ⚠️ 与 §6.2 的 `dt_s` 对照：**`dt_s` 保证的是"给定时间轴时积分正确"，但时间轴本身错了它就救不回来。时间基准必须先于一切时间指标被验证。**

| 对策 | 要求 |
|---|---|
| **优先用逐帧 `cv2.CAP_PROP_POS_MSEC` 构建时间轴**，而非 `帧序号 / 标称FPS` | 强制 |
| 只能拿到标称 FPS 时 | 标 `timing_source='nominal_fps'`，报告显式提示「若为 VFR 录像，所有时间类指标可能存在系统性偏差」 |
| 自检：标称时长 vs 实际解码时长偏差 **> 2%** | 告警 `timing_suspect=True` |

#### ② 时间原点的定义：从哪一秒开始数（语义层，**PM 补充**）

> 上面的 VFR 问题是"尺子准不准"，这一条是"**零点在哪里**"。**两者独立，都要管。**

`t0` 至少有三种合理但**互不相等**的定义：

| 定义 | 时刻 | 枚举值 |
|---|---|---|
| A. 投饵器**启动** | 电机开始转动 | `feeder_start` |
| B. 第一颗饲料**离开投饵器** | — | `pellet_released` |
| C. 第一颗饲料**出现在画面/入水** | — | `pellet_in_frame`（**默认**） |

**A 与 C 之间可能相差 1–3 秒甚至更久**（取决于投饵器到水面的距离、下料速度）。

**为什么必须管**：
1. **T50 / T90 / 响应潜伏期全部以 t0 为零点** —— 定义不同，数值系统性偏移一个常数；
2. **偏移在组间可能不一致** —— 若两组视频由不同人打点、或用了不同的打点习惯，**组间比较会引入系统偏差**，而这在报告上完全看不出来；
3. **响应潜伏期（P0 指标）对 t0 最敏感** —— 它本身的量级就是数秒，偏移 1–3 秒是致命的。

**要求：**
- **默认定义固定为 `pellet_in_frame`** —— 可由视频客观判定、可复现、不依赖外部观察；
- **`t0_definition` 必须写入 `run_config.yaml` 并参与 `compare.py` 校验** —— 依据已定判定标准：「它变了会让两次运行不可比，就必须进 run_config 并被 compare.py 校验」；
- UI 打点时**明确提示当前使用哪个定义**，不允许用户"凭感觉点一下"而不知所点为何；
- **若用户改用 A/B 定义，报告中须注明**，且不得与 C 定义的批次直接比较。

#### ③ `t0` 来源：这个点由谁定的（架构师 v9 补充）

契约原有 `t0` 来源优先级「用户手动打点 > 自动检测」。**结论对，但理由必须换成下面这条**——否则工程师在追求自动化的压力下很可能把它反过来：

> ⚠️ **理由不是"手动更准"，而是"自动检测的偏差与自变量混淆"。**

自动检测判据是"颗粒数首次 >0 且持续"，**它依赖检测器召回**：
- 饲料 A 分散快、颗粒清晰 → 检测器早早检出 → `t0` 偏**早**
- 饲料 B 易结团、初期稀疏 → 检测器漏检 → `t0` 偏**晚**
- → **饲料 B 的 T50 被系统性缩短，看起来"被吃得更快"**

**而"分散快慢"很可能与我们要测的诱食性相关 —— 这是与自变量混淆的系统偏差。**

**它比人工偏差危险得多**：人工偏差至多是常数偏移或随机噪声，**不随处理组变化**；自动检测偏差**随处理组变化**，直接伪造出组间差异。**这是第三个"人为放大组间差异"的入口**（前两个是 N₀ 系统性低估、沉降与摄食不分）。

| 场景 | `t0` 策略 |
|---|---|
| **跨组比较（主场景）** | ⭐ **同一人按固定定义统一打点**；自动值仅作交叉校验 |
| 单次分析 | 自动检测即可，记录 `t0_source='auto'` + `t0_detect_conf` |
| 两者都有 | 都记录，偏差 > 1 s → 告警 `t0_discrepancy` |

**`t0_definition` 与 `t0_source` 均须进 `run_config`，`compare.py` 两个都校验。**

#### ④ 🔴 时间轴不连续：多段拼接 / 录制中断（**PM 补充，第四类**）

> **风险**：用户很可能把「投喂前空镜头」与「投喂过程」**分成两段录制再拼接**给我们 —— **而这恰恰是我们自己在素材清单里要求的素材结构。** 我们引导出了一个会破坏时间轴的行为。

拼接 / 中断续录会导致：时间戳**重置**（重新从 0 开始）或出现**跳变**；而 `POS_MSEC` 若被重置，时间轴会在断裂处折回，**断裂点之后的 T50/T90/起止时刻全部错位**。

| 对策 | 要求 |
|---|---|
| **自检：校验 `POS_MSEC` 序列严格单调递增** | 出现回退 → `timeline_discontinuity=True`，**断裂点之后的时间指标一律不输出** |
| 相邻帧间隔 > 中位数 **3 倍** | 判为跳变，标记断裂位置 |
| 断裂时 | 报告断裂位置（时间戳）；**或按段分别处理**（若每段都有独立 t0 与基线） |

#### ⑤ 🔴 时间轴系统性缩放：慢动作 / 延时模式（**PM 补充，第五类**）

> **风险**：手机「慢动作」（如 120 fps 采集、编码为 30 fps 播放）或「延时摄影」会让**视频内时间 ≠ 真实物理时间**。
> 慢动作 4 倍 → 视频 1 秒 = 真实 0.25 秒 → **所有时间指标被放大 4 倍**。

🔴 **这一类无法从视频文件内部检测**：慢动作文件内部完全自洽（容器标称 fps、帧数、时长三者一致），**文件"认为"事件就是那么长**。只有用户知道真实拍摄模式。

**因此唯一对策是问用户**（已加入 `docs/05` Q3）：

| 确认项 | 处理 |
|---|---|
| 是否使用手机/相机的**慢动作、高帧率慢放、延时摄影**模式 | 若是 → 必须由用户提供**真实拍摄帧率与播放帧率**（或倍率），否则所有时间指标标记 `timing_scale_unknown=True` 并告警 |

> ⚠️ **这条也是我们自己的建议可能诱导的**：我们在素材清单里建议"沉性料用 ≥60 fps、能上 60 更好"。**用户很可能为了实现高帧率而去开手机的慢动作模式**，结果反而让时间轴整体缩放。
> **因此拍摄建议里必须显式加一句**：「请确认使用**正常拍摄模式**，**不要使用慢动作/延时模式**；若需要高帧率，请在相机设置里选择"高帧率录像"而非"慢动作"。」

#### ⑥ 多机位时间对齐（**PM 补充，一期不做但需留位**）

若未来支持俯拍 + 侧拍**双机位融合**（本报告 §3 提到双机位为科研级推荐），**两个视频的时间轴必须对齐**，否则跨机位融合的指标（如 `P_upper` 与 `N_fz` 联合分析）会错。
- 对齐方式：公共参照事件（投饵器动作、灯光变化）或**音频波形对齐**
- 须记录 `sync_method` 与 `sync_offset_s` 进 `run_config`

> **一期不实现多机位融合，但 `run_config` 里预留 `sync_method` / `sync_offset_s` 字段**，避免将来 schema 破坏性变更。

> 📌 **五类风险的完整关系**：
> **VFR** 让"每一秒有多长"不可信（**抖动**）｜**慢动作**让"每一秒有多长"不可信（**恒定缩放**）｜**拼接**让时间轴**断裂**｜**t0 定义**让"从哪一秒开始数"不可信｜**t0 来源**让"这个数由谁定的"不可信。
> **叠加时时间指标会同时偏移、缩放、断裂 —— 而且每一类都不报错。**

## 2. 全局质量信号（Quality Signals）

这些信号**每次运行必算、必输出**，并被各指标的"失效条件"引用。建议放在 `metrics/quality.py`。

| 代号 | 名称 | 计算 | 用途 |
|---|---|---|---|
| `Q_det` | 颗粒检测置信度中位数 | `median(pellet.conf)` 全程 | 颗粒类指标门控 |
| `Q_fdet` | 鱼体检测置信度中位数 | `median(fish.conf)` | 鱼体类指标门控 |
| `Q_vis` | 平均可见鱼数 | `mean(M)` 基线期 + 试验期 | 密度分档 |
| `Q_track` | 可追踪个体比例 | `有效轨迹数(n_frames_alive ≥ min_len) / mean(M)` | 个体类指标门控 |
| `Q_ids` | ID 切换率 | `IDS / (轨迹数 × 帧数 / 1000)` | 个体类指标门控 |
| `Q_interf` | 反光/水花污染帧占比 | 被 exclusion 掩膜剔除面积 > 阈值 的帧占比 | 活跃度门控 |
| `Q_fg` | 前景像素占比 | 背景减除前景面积 / arena 面积 | 光流类门控 |
| `Q_calib` | 标定可用性 | `px_per_mm is not None` | BL 归一化门控 |
| `Q_baseline` | 基线可用性 | `BaselineStats is not None and duration_s ≥ 30` | 相对指标门控 |
| `Q_pelletloss` | 非摄食损失率 | `非摄食消失颗粒数 / N₀` | 清空时间类降级 |
| `Q_n0gap` | N₀ 交叉校验偏差 | `abs(N0_det − N0_meta) / N0_meta` | 所有归一化颗粒指标 |
| `Q_censored` | 右删失标记 | 事件在观察窗内未发生 | 报告标注 |
| `Q_motion` | 相机稳定性 | 帧间特征点配准残差 | 帧差/光流类门控 |

## 3. 指标契约

> **图例**：🔴 P0 ｜ 🟡 P1 ｜ 🟢 P2
### 🔴 采样与输出约定（**v2 修订，原"统一重采样到 1 Hz"已作废**）

> **原契约写"对外统一重采样到 1 Hz 输出"，此条是错的，已废弃。** 由架构师高见远指出。原因：非对称采样下尾段真实间隔可达 10 s，重采样到 1 Hz 等于**凭空插值出 9 个不存在的观测点**；任何人拿这份 CSV 计算 AUC、积分或斜率都会得到与真实数据不同的结果，**而且看不出自己算错了**。

**修订后的规则（三条）：**

**① 原生不规则时间戳是唯一可信源。**
- `metrics_timeseries.csv` 保留**原生不等间隔时间戳**，不可用点写**真空值**（空字符串，非 0）。
- **必须包含 `dt_s` 列**（距上一个采样的真实间隔）。没有它，用户在 Excel 里积分时会默认等间隔而算错——这一列是最便宜的防呆。

**② 所有积分/微分/拟合类指标必须在原生序列上计算，禁止在重采样序列上计算。**
涉及：**A5 v(t)、A6 v_max、A12 (k, τ) 拟合、A13 AUC₆₀、D6 FA_AUC、D7 k_rise、D8 k_fall、B2-10 τ_disp**。
积分一律用**基于真实 dt 的梯形法**（`np.trapz(y, t)`），**不是** `sum(y)/fps`。

> 📌 补充一点，避免矫枉过正：**非均匀采样对积分其实是有利的**——t0 后早期（曲线最陡）采样密、尾段（曲线平缓）采样稀，等于自适应积分，比等间隔更准。所以不要为了"整齐"而压缩尾段。

**③ 1 Hz 版本只能作为可选的画图便利层。**
- 文件：`metrics_timeseries_1hz.csv`，**不是默认导出项**。
- 每行带 `interpolated: bool`（真观测 False / 插值 True）与 `source_interval_s`（该处原生间隔）。
- 文件头必须写明：「**插值数据，不可用于积分、统计或显著性检验**」。
- 图表层（charts.py）**默认绘制原生序列**；若要画平滑曲线，须以原生点为 marker 叠加显示，不得只画插值线。

**④ ⚠️ 区分两种"插值"——不要一刀切禁止。**
| 类型 | 判定 | 示例 |
|---|---|---|
| **合法且应当做** | 在**已有观测之间**插值以定位**事件发生的精确时刻**（不是制造观测） | A8/A9/A10 求 T50/T90/T100 穿越点时做线性插值，提高时间分辨率 |
| **非法** | 制造**不存在的观测点**，并让下游把它当真实数据做积分/统计 | 把 10 s 间隔序列重采样成 1 Hz |

> 求 T50 的线性插值**必须保留**，不要因为上面禁止了重采样就连它一起去掉——两者性质完全不同。

### 3.1 Group A — 饲料/颗粒维度（`metrics/group_a/`）

#### A1 · 初始颗粒数 🔴
| 项 | 内容 |
|---|---|
| **输入** | `PelletDetections` over 早期窗口 `[t0, t0+W]`，`W = min(30 s, 0.1×视频时长)`；`ROI.pellet_zone`；`RunMeta.feed_mass_g`, `RunMeta.pellet_mass_mg` |
| **输出** | `{N0_det: int(颗), N0_meta: float(颗)\|None, W_used: float(s), n_frames: int, peak_conf: float}` |
| **算法约束** | `N0_det` = 早期窗口内 `N(t)` 的**平滑最大值**（取 3 点移动中位数后取 max），**不得用单帧 argmax**（防峰值帧漏检）；`N0_meta = feed_mass_g × 1000 / pellet_mass_mg` |
| **质量分** | `Q_n0gap`, `Q_det`, `n_frames`, `peak_conf` |
| **失效条件** | `n_frames < 3` → **不可用**<br>`RunMeta` 缺项 → 输出 `N0_meta=None`，标记 `cross_validated=False`<br>`Q_n0gap > 0.20` → **降级为参考值 + 告警**（提示可能漏检或投喂量口径不符） |

#### A2 · 剩余颗粒数曲线 🔴
| 项 | 内容 |
|---|---|
| **输入** | 逐帧 `PelletDetections`；`ROI.pellet_zone`；平滑窗口 `w`（默认 5 采样点） |
| **输出** | `TimeSeries(t, N_p)`，单位 **颗**，原生不规则采样；附逐点 `conf_med` |
| **质量分** | 逐点 `conf_med`；`Q_interf`；`n_excluded_frames` |
| **失效条件** | `ROI.pellet_zone is None` → **不可用**<br>单帧 `N > 500`（密集粘连，计数饱和）→ 该帧标 `low_conf=True`，不参与拟合<br>`Q_det < 0.50` → **全局降级 + 告警** |

#### A3 · 累计消耗 C(t) 🔴 ／ A4 · 消耗比例 P(t) 🔴
| 项 | 内容 |
|---|---|
| **输入** | A2 输出；A1 的 `N0_det` |
| **输出** | `C(t) = N0_det − N_p(t)`（颗）；`P(t) = C(t)/N0_det × 100`（%） |
| **质量分** | 继承 A2；附 `N0_source`（`det` / `meta`） |
| **失效条件** | 同 A2 **且** A1 不可用 → 不可用 |

#### A5 · 瞬时消耗速率 v(t) 🟡
| 项 | 内容 |
|---|---|
| **输入** | A2 平滑后序列；平滑方法（Savitzky-Golay，polyorder=1）；单调化开关 |
| **输出** | `v(t) = −dN_p/dt`，单位 **颗/s**，原生不规则采样 |
| **算法约束** | 必须先**单调化**（强制 `N_p` 非增，取累积最小值），否则回补帧（颗粒重新入画/检测器抖动）会产生负速率 |
| **质量分** | 局部信噪比 `|v| / std(残差)`；窗口内有效点数 |
| **失效条件** | 窗口有效点 `< 5` → 该点不输出<br>`N_p` 非单调上升段占比 `> 0.10` → 标记 `counting_unstable=True`，v(t) 仅供定性 |

#### A6 · 峰值消耗速率 v_max 🔴
| 项 | 内容 |
|---|---|
| **输入** | A5；搜索窗口 `[t0, T50]`（**限定在早期，避免尾部噪声**） |
| **输出** | 标量，**颗/s**；附 `t_at_max` |
| **质量分** | 峰值点邻域点数；`Q_det` |
| **失效条件** | 同 A5；若 `T50` 未定义 → 搜索窗口退化为 `[t0, 0.5×窗长]` 并标注 |

#### A7 · T50 段平均速率 v̄₅₀ 🟡
| 项 | 内容 |
|---|---|
| **输入** | `N0_det`, `T50` |
| **输出** | `0.5 × N0_det / T50`，**颗/s** |
| **失效条件** | `T50` 右删失 → **不可用**（不得用窗长代替） |

#### A8 · T50 🔴 ／ A9 · T90 🔴 ／ A10 · T100 🟡
| 项 | 内容 |
|---|---|
| **输入** | A2 平滑序列；`N0_det`；阈值参数 `p ∈ {0.50, 0.10, ε}`，`ε = max(2 颗, 0.02×N0)` 可配 |
| **输出** | 标量，**秒**，线性插值到亚采样精度；附 `censored: bool` |
| **算法约束** | `T = min{t : N_p(t) ≤ p × N0}`，插值求精确穿越点；未穿越 → `T = None, censored=True` |
| **质量分** | 穿越点处局部斜率（越陡越可靠）；穿越点邻域有效帧数；`Q_pelletloss` |
| **失效条件** | **T50**：未穿越 → `censored=True`（**输出 ">窗长"，不得输出 0/NaN**）<br>**T90**：`Q_pelletloss > 0.15` → **降级为参考值**，必须与 A14 一起展示<br>**T100**：同上，**且在任何情况下都不得单独作为"吃完时间"对外，必须并列展示 `Q_pelletloss`**<br>`RunMeta.pellet_type == 'sinking'` → T90/T100 **强制降级为参考值**（沉降与摄食不可分） |

#### A11 · 残留率 RR 🔴
| 项 | 内容 |
|---|---|
| **输入** | `N_p(T_end)`；`N0_det`；`T_end = min(t0 + 300 s, 视频末帧)`（观察窗默认 300 s，可配） |
| **输出** | `RR = N_p(T_end)/N0 × 100`，**%**；附实际窗长 |
| **质量分** | `Q_pelletloss`；实际窗长是否达到 300 s |
| **失效条件** | 视频短于观察窗 → 改用视频末帧，`window_truncated=True`<br>`Q_pelletloss > 0.15` 或 `pellet_type == 'sinking'` → 标记 `contains_non_feeding_loss=True` |
| **备注** | **建议作为"吃完程度"的主指标**（不依赖"清零"这个不稳定事件，跨组可比性最好） |

#### A12 · 衰减拟合参数 k, τ 🟡
| 项 | 内容 |
|---|---|
| **输入** | A2 全程序列；模型选择 `['exp', 'weibull', 'logistic']`（默认 `exp`） |
| **输出** | `k`（1/s）、`τ = ln2/k`（**s**）、`R²`、`RMSE` |
| **质量分** | `R²`（< 0.80 告警）；有效点数 |
| **失效条件** | 有效点 `< 8` → 不拟合<br>`R² < 0.60` → **不输出**（拟合失败比给错参数好） |

#### A13 · AUC₆₀ 🟡
| 项 | 内容 |
|---|---|
| **输入** | A3 的 `C(t)`；积分区间 `[t0, t0+60 s]` |
| **输出** | `∫C(t)dt`，**颗·s** |
| **失效条件** | 观察窗 `< 60 s` → 改用实际窗长，`window_truncated=True` |

#### A14 · 非摄食损失率 🟡（**质量警示项，不参与主指标计算**）
| 项 | 内容 |
|---|---|
| **输入** | 颗粒 `track_id` 的**消失事件**分类：消失位置落在 `ROI.bottom_band` 或 `ROI.arena` 边界带 → 计为非摄食损失；消失位置邻域（半径 r）内存在 `FishDetections.bbox` → 计为摄食；否则 → `unknown` |
| **输出** | `{n_loss: int(颗), n_eaten: int, n_unknown: int, ratio: %}` |
| **质量分** | `n_unknown / (n_loss + n_eaten + n_unknown)`（未知占比越高越不可信） |
| **失效条件** | `PelletDetections.track_id is None` → **不可用，且必须显式声明"未校正沉降损失"**（**严禁默认为 0**）<br>`ROI.bottom_band is None` → 分类退化为"边界 vs 邻域鱼"两分，标记 `coarse=True` |

### 3.2 Group B1 — 活跃度／运动强度（`metrics/group_b1/`）

> ⚠️ **架构硬约束：`aggregator.py` 严禁把 B1 与 B2 合成为单一标量。** 诱食性强时二者运动方向相反（活跃度↑、ANND↓），合并会抹掉最有判别力的信号。

#### B1-1 · 帧差能量 M_diff(t)（CVFAI 核心）🔴
| 项 | 内容 |
|---|---|
| **输入** | 连续灰度帧；`ROI.arena`；`ROI.exclusion` 掩膜；`BaselineStats.activity_mean/std`；重叠系数（可选：`前景面积 / Σ检测框面积`，用于校正鱼体互相遮挡造成的低估） |
| **输出** | 归一化活跃度 `M_diff_norm = (M_diff − μ_base)/σ_base`，**无量纲**，原生不规则采样 |
| **算法约束** | `M_diff = Σ|I_t − I_{t−1}|`（灰度，仅 arena ∩ ¬exclusion） |
| **质量分** | `Q_interf`；`Q_motion`；`overlap_coefficient` |
| **失效条件** | `Q_motion` 显示相机晃动（配准残差 > 阈值）→ **不可用**<br>`Q_interf > 0.30` → **降级**<br>`Q_baseline = False` → 只能输出**原始未归一化**量，标记 `uncalibrated=True` |

#### B1-2 · 光流幅值 M_flow(t) 🟡
| 项 | 内容 |
|---|---|
| **输入** | Farneback 稠密光流；`ROI.arena` / `exclusion`；`BaselineStats.flow_mean/std` |
| **输出** | `mean‖(u,v)‖`，**px/s** → **mm/s**（需 `Q_calib`）；归一化版同 B1-1 |
| **算法约束** | **必须扣除全局漂移**：在背景静止区（池壁/投饵框）估计全局流场并减去，否则曝气/循环水流会污染 |
| **质量分** | `Q_motion`；`Q_interf`；全局漂移量 |
| **失效条件** | 同 B1-1；全局漂移 > 信号幅度 → **不可用** |

#### B1-3 · 傅里叶频谱活跃度 🟡（**L0 主通道：唯一不需要检测到鱼的活跃度指标**）
| 项 | 内容 |
|---|---|
| **输入** | 灰度帧 → RGB→HSV → 背景/波纹减除 → 饱和度亮度阈值增强 → FFT → 环形滤波器组幅值和 → 特征向量；可选轻量 SVM |
| **输出** | **已标定版**：活跃度评分（需 SVM）；**未标定版**：`频谱幅值和 / 基线幅值和`，无量纲 |
| **质量分** | `calibrated: bool`；频谱幅值动态范围 |
| **失效条件** | 无标注 → **只能输出未标定原始量，必须标 `calibrated=False`**（**严禁把未标定值当作已验证指标对外**）<br>需 ≥20 段有/无摄食标注片段才能训练 SVM<br>`Q_interf > 0.30` → 降级（波纹频谱会被反光污染） |

#### B1-4 · 混合熵 H = H_v / H_θ 🟡
| 项 | 内容 |
|---|---|
| **输入** | 前景掩膜（背景减除或检测框并集）上的 LK 稀疏光流 → 每个光流矢量的速度 `V` 与转角 `θ` → 直方图 → 熵 |
| **输出** | `H_v`（bit）、`H_θ`（bit）、`H = H_v / H_θ`（无量纲），原生不规则采样；附全程统计量 |
| **质量分** | `Q_fg`（前景像素占比）；前景内光流矢量数 |
| **失效条件** | `Q_fg < 0.01`（前景太少，看不清鱼）→ **不可用**<br>光流矢量数 `< 50` → 直方图不可靠，不输出 |

#### B1-5 · 群体平均游速 Ū 🟡
| 项 | 内容 |
|---|---|
| **输入** | `FishDetections` + `Tracks`；`px_per_mm`；`body_length_mm` |
| **输出** | **px/s** → **mm/s** → **BL/s**（三级，能算到哪级算到哪级，每级都输出） |
| **算法约束** | 位置序列必须先**平滑**（样条/移动平均）再差分，否则像素噪声被一阶差分放大 |
| **质量分** | `Q_track`；`Q_ids`；`Q_calib` |
| **失效条件** | `Q_track < 0.50` 或 `Q_ids` 超阈值 → **关闭**<br>`Q_calib = False` → 只输出 px/s，标记 `unscaled=True`<br>`body_length_mm is None` → 不输出 BL/s |

### 3.3 Group B2 — 聚集度／空间分布（`metrics/group_b2/`）

#### B2-1 · ANND 平均最近邻距离 🟡
| 项 | 内容 |
|---|---|
| **输入** | 逐帧鱼体**质心**（检测框中心即可，**不要求分割**）；`N`；`px_per_mm`；`body_length_mm` |
| **输出** | `D_nn = (1/N)Σ_i min_{j≠i}‖B_i − B_j‖`，**px** → **mm** → **BL**（三级都输出） |
| **质量分** | `N`；`Q_fdet`；`Q_calib` |
| **失效条件** | `N < 5` → **不可用**（ANND 方差爆炸）<br>`Q_calib = False` → 只输出 px，**标记 `unnormalized=True`（不可跨视频比较）** |

#### B2-2 · MDC 平均中心距离 🟡 ／ B2-3 · R90 分布半径 🟡
- **输入/输出/质量分/失效条件** 同 B2-1（`MDC = (1/N)Σ‖B_i − B̄‖`；R90 = 含 90% 个体的最小圆半径）

#### B2-4 · FIFFB（Delaunay 群集指数）🟡
| 项 | 内容 |
|---|---|
| **输入** | 逐帧质心集合；`scipy.spatial.Delaunay`；`px_per_mm` |
| **输出** | Delaunay 三角形**平均周长**，**px** → **mm** |
| **质量分** | `N`；质心重复率（重叠鱼被检成 1 个时方差剧增） |
| **失效条件** | `N < 8` → **不可用**（Delaunay 需 ≥3，但 <8 时指标极不稳）<br>质心重复率 > 阈值 → 标记 `degenerate=True` |
| **备注** | 文献校验最强（与专家评分 **r=0.945**），**建议优先实现** |

#### B2-5 · 投喂区鱼数 N_fz 🟡 ／ B2-6 · 占比 P_fz 🔴
| 项 | 内容 |
|---|---|
| **输入** | 质心；`ROI.feed_zone`；`RunMeta.n_fish_total` |
| **输出** | `N_fz`（**尾**）；`P_fz = N_fz / N_total × 100`（**%**） |
| **质量分** | `Q_fdet`；`Q_vis` |
| **失效条件** | `ROI.feed_zone is None` → **不可用**<br>`n_fish_total is None` → 只输出 `N_fz` 绝对值，标记 `no_denominator=True` |

#### B2-7 · RP 相对偏好系数 🔴 ⭐
| 项 | 内容 |
|---|---|
| **输入** | `N_fz(t)` 在试验窗的均值；`BaselineStats.n_fz_mean`；`BaselineStats.n_fz_std` |
| **输出** | `RP = mean(N_fz) / n_fz_mean`，**无量纲** |
| **质量分** | `Q_baseline`；基线时长；`n_fz_std / n_fz_mean`（基线变异系数） |
| **失效条件** | **`Q_baseline = False` → 强制关闭**（RP 的定义就是相对基线，无基线即无意义）<br>**`n_fz_mean < 1` → 不可用**（除零风险 + 基线无鱼则比值无意义）<br>基线变异系数 `> 0.5` → 降级，标记 `unstable_baseline=True` |
| **备注** | **诱食性最对口的指标**；只需检测器、不需跟踪，L1 阶段即可稳定产出 |

#### B2-8 · CAI 综合聚集指数 🟢
| 项 | 内容 |
|---|---|
| **输入** | `ANND`, `MDC`, 热力图密度值, 密度峰值数；权重 `w_k`（默认等权，可配） |
| **输出** | `CAI = Σ w_k · f_k(normalized)`，无量纲 |
| **质量分** | 可用分量数 / 总分 量数 |
| **失效条件** | 任一分量为 `None` → 用可用分量子集计算并标注 `partial=True`；**可用分量 < 2 → 不可用** |

#### B2-9 · 局部密度峰值 D_peak 🟢
- 输入：质心 → 高斯核密度图（σ 建议 = 1 倍体长）；输出：归一化密度峰值
- 失效条件：同 B2-1（`N < 5` 不可用）

#### B2-10 · 聚集衰减时间常数 τ_disp 🟢
- 输入：聚集度曲线峰值后段 → 指数拟合
- 失效条件：峰值后有效点 `< 5` → 不拟合

#### B2-11 · 上层鱼占比 P_upper 🟢
- 输入：**侧拍机位** + 画面纵向分带 + 质心
- 失效条件：机位为俯拍 → **不可用**（架构层应检测机位类型并关闭）

### 3.5 Group D — 全局/时序（`metrics/group_d/`）

| ID | 指标 | 输入 | 输出 | 质量分 | 失效条件 |
|---|---|---|---|---|---|
| D1 | 活跃度时序 FA(t) 🔴 | **仅 B1 分量加权融合**（严禁混入 B2） | 归一化无量纲，原生不规则采样 | 可用分量数；Q_interf | 所有 B1 分量均不可用 → 不可用 |
| D2 | 摄食起始 T_start 🔴 | FA(t) 或 颗粒首次减少；判据 `> μ_base + 3σ_base 且持续 ≥1 s` | **s** | Q_baseline | 基线缺失 → 退回"颗粒首次持续下降"口径并标注 `fallback=True` |
| D3 | 饱和时刻 T_end 🔴 | FA(t)；判据 `< μ_base + 2σ_base 且持续 ≥3 s`（**阈值可配**） | **s**，附 `censored` | Q_baseline | 窗内未回落 → `censored=True`（输出 ">窗长"） |
| D4 | 摄食持续时长 Dur 🔴 | D3 − D2 | **s** | 同 D2/D3 | 任一为 None → 不可用 |
| D5 | 活跃度峰值 FA_peak 🟡 | FA(t) / 基线 | 无量纲 | Q_baseline | 基线缺失 → 只出绝对值 |
| D6 | 活跃度 AUC 🟡 | ∫(FA − FA_base)dt over [T_start, T_end] | 无量纲·s | 同 D4 | 同 D4 |
| D7 | 上升斜率 k_rise 🟡 | (FA_peak − FA_base)/(T_peak − T_start) | **1/s** | 同 D4 | 同 D4 |
| D8 | 下降斜率 k_fall 🟡 | (FA_peak − FA_base)/(T_end − T_peak) | **1/s** | 同 D4 | 同 D4 |
| D9 | 时序动作片段 Segments 🟢 | BMN 类模型 + 训练 | `[start, end, score]` | 模型 score | **默认关闭**；需时序边界标注训练 |
| D10 | 强度分类序列 Level(t) 🟢 | 分类模型 | 4 档标签 | 模型 score | **默认关闭**，仅作辅助可视化，**不得作为计量结论** |

## 4. 降级矩阵（`capability.py` 驱动逻辑）

### 4.0 元规则：谁有权关闭指标（**架构师 v3 决策 2，优先于下面所有分档规则**）

> **任何*自动推断*的分类（摄食烈度档 VIGOROUS/GENTLE、机位类型、鱼种等），只被允许追加 ⚠️ 标记，绝不允许触发 ❌ 关闭。**
>
> **只有两类东西有权关闭指标：**
> ① **实测质量信号** `Q_*`；
> ② **用户显式提供的元数据**（`RunMeta` 中非空字段）。
>
> 推论：自动判据的 `UNKNOWN` 结果一律按**更保守的分支处理**（加标记，不关闭）。例如烈度档 `UNKNOWN` → 按 `GENTLE` 分支加 `low_sensitivity` 标记，但**不关闭任何指标**。
>
> **UI 要求**：烈度档、饲料类型、机位类型必须做成**必填下拉框 + 自动判据预填的默认值**——纯提示（非必填）用户一定会跳过，那这些字段就永远是 UNKNOWN。

> 📌 **本条修订说明**：我原先在 §8 建议"烈度档自动判据不可靠，建议只作提示、别用它驱动降级"。架构师将其升格为架构级元规则（直接取消自动判据的关闭权限），**比我的建议更硬、更好，采纳**。

### 4.3 🔴 「因变量混淆」型偏差（**误差幅度依赖于被测变量**）

> **这类偏差的杀伤力远大于普通精度问题**：**即使两组真实值完全相同，也可能测出显著差异。** 普通精度问题只是让数不准；**混淆型偏差会伪造出本来不存在的结论。**
>
> 判定标准：**测量误差的幅度，是否依赖于我们正在测的那个量？** 是，即为本类，必须阻断或显式标记（**不能只降级**）。

| # | 机制 | 误差依赖什么 | 对策 | 状态 |
|---|---|---|---|---|
| **1** | **颗粒重叠 → 计数召回** | 高诱食性 → 吃得快 → 密度下降快 → 重叠轻 → 召回**高**；低诱食性 → 堆积 → 召回**低** | `Q_n0gap` 交叉校验 + `denominator_suspect` | 已在阻断清单（第 2 项） |
| **2** | **鱼体重叠 → 计数/点模式统计** | 高诱食性 → 聚集更紧 → 框合并 → ANND/MDC/R90/FIFFB/D_peak 基于错误点数计算 | `Q_overlap` + `fish_count_confounded` | 已在阻断清单（第 8 项） |
| **3** | **饲料分散性 → t0 自动检测** | 饲料 A 分散快 → 早检出 → t0 偏早；饲料 B 初期稀疏 → 漏检 → t0 偏晚 → T50 被系统性缩短 | 人工统一打点 + `t0_source` 进 run_config | 见 §1 ③ |
| **4** | ⭐ **运动模糊 → 跟踪质量 → 指标可用性** | **见下方详述** | **新增** | ⬇️ |
| 5 | 聚集 → 遮挡颗粒 → `N_p` 偏高 | 聚集越密，被鱼体挡住的颗粒越多 → 剩余数高估 → 消耗速率低估 | 由 `Q_overlap` 部分捕捉；**方向偏保守（削弱真实效应）**，不单列指标 | 仅记录 |

#### ⭐ 第 4 类（PM 补充）：**缺失本身也可以是混淆的**

> **机制**：活跃度高（抢食激烈）→ 鱼游速快 → **运动模糊加剧 + 帧间位移增大** → `Q_track` 下降、`Q_ids` 上升 → **C 组（个体级指标）被 `capability.py` 整组关闭**。
>
> **即：游得越快 → 速度测量越不准，乃至不可测。**

**它比前三类更隐蔽，因为它造成的是"缺失"而非"偏差"：**

- 我们**恰恰在最需要测量的时候测量质量最差**；
- 更严重的是 **C 组包含游速本身**，所以**在高诱食性组，游速指标会系统性缺失；在低诱食性组可得**；
- 于是**"哪些指标被输出"不再随机** —— 这在统计上叫**非随机缺失（informative missingness）**，它引入的选择性偏差**比数值偏差更难察觉**：用户看到的是"这组没有游速数据"，而不会意识到**缺失本身就是一个结果**。

**两条工程对策：**

1. **报告中必须列出"本组因何原因未输出哪些指标"**（`capability_report.md` 已有 `disabled_with_reason`，**此处升级为强制**），且**不得静默省略**。
2. **`compare.py` 第 6 条规则**：**若两组的"已关闭指标集"不同 → 必须告警**，提示"两组的可用指标不一致，直接比较可得部分可能产生选择性偏差"。**这是 compare.py 目前唯一没管的一类可比性。**

> 📌 **由此得出一条通则**（架构师建议收紧一档，PM 采纳）：
> **问"这个门的触发条件是否与我们正在测量的效应相关"。相关 → 非中立门控，其关闭具信息性；不相关（纯外部条件）→ 中立门控。**
>
> （原表述"这个门会不会只在一部分组里关上"会被误解为"只要组间不同就危险"，但**不同养殖单元导致的组间不同是合法的**。）

#### ⚠️ 聚集度指标在重叠下的表现：**以真值实测决定，不靠推理定论**（本小节为 v5 修订）

**架构师 v12 观察**：ANND / MDC 的定义含 `1/N`，而重叠会使 `N` 被低估 → 判定为"**双重污染**"（点位置错 + 分母错），FIFFB 不除 N → "单重"，故建议高 `Q_overlap` 时以 FIFFB 为主。

**PM 复核意见：结论方向可采纳，但机制论证不成立，需改为实测判定。** 三点：

**① "单重 vs 双重"的区分在理论上不成立**

> ANND 与 FIFFB **都随点密度缩放**（随机点格局下 ANND ≈ 0.5/√密度；Delaunay 平均周长同样 ∝ 1/√密度）。
> 因此**点丢失会让两者同向膨胀**，并非"一个双重、一个单重"。`1/N` 只是把求和变成**均值**，它本身不构成第二个独立误差源。
> MDC 反而可能**更稳健**（聚成一团时，合并产生的点仍落在团内，均值偏移小）。

**② 但偏差的"方向"是明确的，这一点比"哪个指标更好"更重要**

> 重叠导致的膨胀是**向零衰减**的：
> - 真值：高诱食性组聚集紧（ANND 小）vs 低诱食性组分散（ANND 大）
> - 实测：高诱食性组因重叠膨胀更多，低诱食性组膨胀少
> - ⇒ **实测组间差 < 真实组间差，效应被系统性削弱**
>
> **这是"掩盖真实效应"（假阴性），而非"伪造差异"（假阳性）——危害性质与 N₀ 低估不同，但同样严重：**
> ⭐ **尤其危险的是：衰减幅度与效应大小成正比 ⇒ 会压缩剂量-响应曲线。在剂量梯度实验（问卷 Q18）中，这会让真实存在的剂量效应看起来更平，甚至呈现假的平台期。**

**③ 🔬 因此不做理论裁定，改由真值实测决定，且运行时数据驱动**

> 我们在 §7.1 已要求采集「**鱼群聚集最紧的时刻 ≥2 帧**」的真值。用同一批帧即可直接算出：
> **在同一 `Q_overlap` 水平下，ANND / MDC / FIFFB 各自的「实测值 vs 真值」误差。**
>
> **工程要求**：验证报告按 `Q_overlap` 分档给出三者的误差曲线；**报告中选谁为主，由该曲线决定，不写死在代码里**。
>
> 这与架构师为 `inferentially_valid` 定的要求是同一条原则：**判据数据化，新增指标或换场景时才不必改代码。**

> 📌 **过渡期建议**（实测数据到位前）：以 **FIFFB 为主**——依据不是"单重污染"，而是**它是文献校验最强的单项（与专家评分 r=0.945）**。ANND / MDC 作参考并一律标注 `fish_count_confounded`。

**④ RP 的一处修正（PM 补充，架构师 v12 遗漏）**

> 架构师称"RP 的分母是基线期鱼数，效应发生前测量，天然效应无关，不用改"。
> ⚠️ **只对了一半：分母安全，但分子不安全。**
> `RP = mean(试验窗 N_fz) / 基线期 N_fz` —— **分子 `N_fz` 是在效应发生期间测量的，同样受重叠影响。**
> ⇒ **RP 仍需按 `fish_count_confounded` 处理**，只是**不存在"分母也被污染"这第二层**。
>
> `P_fz` 同理：分母是用户声明的常数（安全），分子 `N_fz` 受重叠影响（不安全）。

#### 🔍 `Q_fg` 是否中立？—— **不中立，但原因与直觉相反，且可修复**（回应架构师 v11 提问）

`Q_fg`（前景像素占比）是 B1-4 混合熵的门控。架构师猜测"鱼多/聚集 → Q_fg 上升"。**实际机制比这复杂，且方向可能相反：**

| 机制 | 方向 | 说明 |
|---|---|---|
| ① **前景不只含鱼** | 污染 | 背景减除会把**饲料颗粒、水花、气泡**一并算作前景。**投喂后早期颗粒最多 → `Q_fg` 虚高**，与剩余颗粒数相关 |
| ② **聚集导致重叠** | **反向** | 鱼聚拢 → 互相遮挡 → **投影面积反而下降**。故高诱食性（聚集紧）组的 `Q_fg` 可能**更低** |
| ③ 门控在低端触发 | — | `Q_fg < 0.01` 只在"几乎看不到鱼"时触发，主要与密度/能见度相关 |

**修复措施（必须做）：**

> 🔧 **`Q_fg` 的计算区域必须排除 `ROI.pellet_zone`**（或直接扣除检测到的颗粒区域）。
> 否则 `Q_fg` 会被颗粒数污染 —— **而颗粒数是 A 组正在测的量**，等于用一个被测变量去门控另一个指标。

**修复后仍按非中立门控处理**（机制 ② 使高聚集组前景面积下降，可能更接近低端阈值）。

#### 🔴 但还有一层更关键的问题：`Q_fg` 不只是门控，它可能是归一化因子

> **只要把活跃度按「鱼数」或「前景面积」归一化，就会引入混淆。**
>
> **规则：活跃度指标一律以固定的 `ROI.arena` 面积归一化，绝不以鱼数或前景面积归一化。**
> 因为 `ROI.arena` 是外部给定的、与效应无关的量；而鱼数与前景面积都随效应变化。

#### ⭐ 由此得出：B1 的"中立性"必须细分到**子指标级**，"B1 整组中立"不成立

| B1 子指标 | 主要门控 | 中立? | 结论 |
|---|---|---|---|
| **B1-1 帧差能量** | `Q_interf` / `Q_motion` | ✅ **中立**（外部环境） | ⭐ 跨组比较主力 |
| **B1-2 光流幅值** | `Q_interf` / `Q_motion` | ✅ **中立** | ⭐ 跨组比较主力 |
| **B1-3 傅里叶频谱** | `Q_interf` + 标定状态 | ✅ **中立**（标定属外部条件） | ⭐ 跨组比较主力（需已标定） |
| **B1-4 混合熵** | `Q_fg` | ⚠️ **非中立**（见上），修复后近似中立但仍需标 `fish_count_confounded` | 支持性证据 |
| **B1-5 群体平均游速** | `Q_track` / `Q_ids` | 🔴 **非中立**（依赖跟踪，性质同 C 组） | ⚠️ **应重新归类到 C 组** |

> **B1-5 是一个归类错误**：它虽然叫"群体平均"，但**依赖逐条鱼的稳定跟踪**，本质是 C 组指标做了群体聚合。**它不该享受"B1 中立"的待遇**，否则会污染"B1 可用于跨组统计推断"这个结论。

### 4.4 `compare.py` 拒绝规则汇总（**七条**）

| # | 触发条件 | 行为 |
|---|---|---|
| 1 | 两个 run 的 `px_per_mm` 不一致 | 拒绝比较任何带 `unnormalized` 的指标，并列出被拒指标及原因 |
| 2 | 两个 run 的 `metrics_spec_version` 不一致 | **拒绝整份比较** |
| 3 | **模型 md5 不一致**（架构师 v10） | **拒绝全部比较** —— 换/重训模型 → 检测行为整体改变 → 几乎所有指标不可比。这比 `metrics_spec_version` 更根本 |
| 4 | **`window_s` 不一致 或 任一 run `window_truncated=True`** | **拒绝比较 RR 与清空时间类** —— RR@300s 与 RR@180s 不是同一个量 |
| 5 | **ROI 多边形不一致**（面积差 >5% 或 IoU <0.95） | **告警，不拒绝** —— 不同养殖单元时 ROI 本应不同（合法），系统无法判断是哪一种 |
| 6 | **两组的"已关闭指标集"不同**（PM 补充，见 §4.4） | **告警** —— 缺失可能是非随机的，直接比较可得部分会产生选择性偏差 |
| 7 | **缺失由非中立门控触发**（`Q_track`/`Q_overlap`/`Q_det`/`Q_fg`，架构师 v11） | 🔴 **拒绝对"可用子集"做统计推断** —— 只对碰巧有数据的组做检验 = **以结果为条件抽样**，典型选择性偏差，且比数值错误更难发现。<br>**必须同时给出出路**：「请改用 B1-1/2/3（帧差能量 / 光流幅值 / 傅里叶频谱）做跨组比较」 |

> ⚠️ **第 7 条不提供"用户确认后覆盖"的开关**（PM 判断）：
> 覆盖开关会诱导用户绕过保护，而这类偏差**不可察觉**（沿用我们已定的"会把用户推向作弊的报错比不报错更糟"）。
> 既然 **B1-1/2/3 这条出路始终可用且成本为零**，就不需要给用户一个"我确认继续"的按钮 —— **给一条更好的路，而不是给一个绕过防护的开关。**

> ⭐ **「拒绝 vs 告警」的判定原则（架构师 v10，PM 采纳）**：
> **"拒绝"只用于"两个 run 本应可比但参数不一致"；"告警"用于"可能合法、需要用户判断"。**
> **核心判据：只有当补救成本极低（重跑约 4 秒）时才拒绝** —— ROI 不一致可能是合法的，拒绝会误伤。
> 这条原则可被推广到将来新增的任何规则，比逐条拍板更可靠。

### 4.6 🔴 衰减型偏差（假阴性）—— 质量体系的**方向性缺口**（架构师 v13 指出，PM 扩充）

> **缺口**：我们整个质量体系（`blocking_flags` / 失效条件 / 能力降级）**全部是"防假阳性"的**——每一个 flag 的含义都是"这个数值有已知缺陷 → 别信它"，用于阻止用户得出**不存在的结论**。
> **但没有任何机制提示"真实效应可能被掩盖"（防假阴性）。**
>
> **这在研发筛选场景下代价更高**：假阳性至少还能被后续实验证伪；**假阴性是你直接把有效候选淘汰了，永远不会再回头验它。**

#### ① 层级定位：**报告级，不属于 `blocking_flags`**

> 关键区分：衰减型偏差判断的是**跨 run 的模式**，而不是单个数值的缺陷。
> **因此它不能放进 `blocking_flags`（那是 metric 级的），必须独立成节。**
> 我们现有的指标体系里没有"**跨 run 模式**"这一层，**这是新增的一层。**

#### ② ⭐ 可计算诊断量（**不需要真值，纯靠内部量即可算出**）

架构师 v13 提出 `corr(剂量/处理水平, Q_overlap)`。**PM 将其推广到全部非中立门控**：

> **通用形式：把非中立门控本身当作"结果变量"来报告组间差异。**
> 对每一个非中立门控 `Q_track` / `Q_overlap` / `Q_det` / `Q_fg`：
> - **剂量梯度实验**：报告 `corr(处理水平, Q)`
> - **两组 A/B 比较**：直接对 `Q` 做组间差异检验（等价于"把门控当结局"）
>
> **任何显著相关/显著差异都是警告信号** —— 它意味着"**测量误差的幅度随处理水平变化**"，即 §4.3 定义的混淆成立。

**判定与触发：**

| 条件 | 行为 |
|---|---|
| `corr(处理水平, Q) > 0.5` 或组间差异显著 | 在报告「效应可能被低估的情形」一节显式列出该门控及其守护的指标 |

**⭐ 符号规则（方向判定，PM 补充）**：

> 就本项目**已知的重叠类偏差**而言（ANND / MDC / FIFFB 被膨胀、`N_fz` 被低估），方向是确定的：
> - **`corr > 0`（门控随处理水平上升）→ 衰减型**：高处理水平组测量误差更大，效应被系统性削弱，**掩盖真实差异**
> - **`corr < 0`（门控随处理水平下降）→ 膨胀型**：高处理水平组测量更准，**可能放大组间差异**（假阳性方向）
>
> ⚠️ **此符号规则仅适用于方向已明确的偏差**。新增指标或新门控时，**必须先确定该偏差的符号，再套用本规则**——不要在方向未知时假定它。

**②‑b 剂量梯度专项**（架构师 v13）：
> 触发时报告必须写明：「**平坦的剂量-响应曲线不能作为『无效』的证据**」。
> 理由：衰减幅度与效应大小成正比 ⇒ **会压缩剂量-响应曲线**，使真实存在的剂量效应呈现假的平台期。

#### ③ 真值采集须覆盖剂量两端（对 §7.1 的补充）

除"聚集最紧时刻 ≥2 帧"外，**剂量梯度实验须在低端与高端各采真值帧** —— **压缩差异最大的地方就在两端**，只采中间测不出这个偏差。

#### 📌 元观察：原则 4 对**原则本身**同样适用

> 我们 §0.5 第 4 条原则说："**数值必须与其适用边界一同传递，边界不得只留在文档里。**"
> **这条原则对它自己同样成立**：设计原则如果只写在文档末尾的清单里，下次决策时**我们不会想起来用**。
>
> 架构师 v13 指出第三类错误："**自己定的原则，下一次自己没想起来用**"——并给出对策：**在关键决策点放检查清单**。
> **这恰恰是原则 4 的自我应用：把原则放在使用它的地方，而不是放在文档里。**

### 4.5 硬规则（无论分档如何，一律生效）

1. `pellet_type == 'sinking'` → **T90 / T100 强制标记 `contains_non_feeding_loss=True`，且必须与 A14 并列展示**。<br>**`pellet_type == UNKNOWN` → 不关闭、不降级，但必须加 `sedimentation_risk_unassessed=True` 标记**（依据 §4.0 规则：未确认的元数据只能追加 ⚠️，不得触发关闭）。<br>`pellet_type == 'floating'` → 无附加标记（浮力料沉降损失可忽略）。
2. `Q_pelletloss > 0.15` → 同上。
3. `A14 不可用` → **任何清空时间类指标都不得声明"已校正沉降损失"**。
4. `Q_baseline = False` → **RP、所有 `_rel`/归一化活跃度/聚集度 强制关闭**（只保留绝对值口径并标注）。
5. `Q_n0gap > 0.20` → 所有以 `N0` 为分母的指标标记 `denominator_suspect=True`。
6. **B1 与 B2 严禁合成为单一标量。**
7. 🔴 **元数据与实测矛盾时必须告警**（**PM 补充**：前 6 条都是防"我们的输出骗人"，这一条防"**喂进来的数据骗人**"）。

   > 我们全程假设用户提供的 `RunMeta` 是对的，但**元数据同样可能填错**，而且**没有任何校验手段**——除了用实测值反查。

   #### ⚠️ 前置质量门（**架构师 v8 指出，不补则本条自己违反原则 1**）

   > **`Q_pelletloss` 依赖 A14 → A14 依赖颗粒轨迹关联 → 关联依赖 `v_sink_max` 标定与密集窗口。**
   > **若 A14 自身不可靠（`partial_window=True` / `coarse=True` / 关联未建立），`Q_pelletloss` 就没有资格覆盖用户的显式声明。**
   >
   > 更要命的是话术：在 A14 不可靠时说"已按**实测值**覆盖您的声明"，等于**声称我们测到了某个东西，而我们并没有可靠地测到**。
   > **这违反原则 1（不得给出无法兑现的承诺），是同一盲区第四次出现**：① 没检出 flag ≠ 可信；② 未版本化 ≠ 跨批可比；③ 误差测不出 ≠ 误差为零；④ **没可靠测到 ≠ 测到了**。

   **修正为三段式：**

   | A14 状态 | 实测 vs 声明 | 行为 |
   |---|---|---|
   | **A14 = ok** | 矛盾 | **采用实测**：「实测显示存在显著沉降损失，已按沉性料规则处理。**若您确认饲料为浮性，请检查 `ROI.bottom_band` 是否覆盖了排水口/溢流区**」 |
   | **A14 = 降级/不可用** | 矛盾 | **不覆盖声明，但也不输出干净的 T90/T100** —— 标 `sedimentation_risk_unverifiable`，按保守分支处理：「**无法验证沉降损失（A14 不可用），已按保守方式处理**」 |
   | 任意 | 一致 | 正常 |

   > **关键原则：无法验证时落到更保守的分支（更多告警），而不是保留用户那份"干净的"声明。**
   > 两种情况**动作相同**（都不给干净 T90），但**理由与话术必须不同** —— **不能把"没测出来"说成"测到了"**。
   > （第一行附带的排查引导由架构师补充：浮性料却测出高损失，常见原因是排水口/溢流区被误判为"沉降"。**给用户的告警要带可执行的下一步**，否则他不知道怎么办。）

   **其余可反查的 `RunMeta` 字段（架构师推广）：**

   | 字段 | 反查依据 | 矛盾时 |
   |---|---|---|
   | `pellet_type` | `Q_pelletloss` | 见上（须先过 A14 质量门） |
   | `feed_mass_g` + `pellet_mass_mg` | `N0_det` | 已有（规则 5） |
| **`n_fish_total`** | `Q_vis`（平均可见鱼数） | `Q_vis > n_fish_total` → `denominator_suspect`。**直接污染 `P_fz` 与 RP 的分母**（RP 是 P0 主指标） |
   | **`body_length_mm`** | 画面内实测体长 × `px_per_mm` | 偏差大 → `Q_bodylen` 来源可疑，BL/s 降级 |
   | **`px_per_mm`** | 已知尺寸参照物 | 自检失败 → `Q_calib=False`，所有 mm/BL 降级 |

   > ⚠️ **`n_fish_total` 的检验是单向的（PM 补充）**：
   > **只在 `Q_vis > n_fish_total` 时告警**。反向（`Q_vis` 远小于 `n_fish_total`）是**正常现象**——遮挡、鱼游出画面、贴边都会让可见数低于总数。
   > 若写成 `abs(Q_vis − n_fish_total) > X` 会**持续误报**，用户很快就会学会忽略这个告警，反而失去防护作用。
   > 另：触发时**最可能的原因是检测器重复计数/误检杂物，而不是用户数错了鱼** —— 排查引导应指向检测器复核。

   > **处理原则：实测优先于声明，但必须让用户知道我们覆盖了他的输入。** 静默采用声明 → 可能输出错的干净结论；静默采用实测 → 用户不知道自己填错了。**两者都要避免，所以是"覆盖 + 告知"。**

   **管线顺序约束（架构师 v8）**：输入侧校验需要"第一遍指标"先算出来才能反查，故顺序为
   `ingest（含时间基准校验）→ 检测/跟踪 → 第一遍指标（A1 N₀ / A14 / Q_vis）→ ★ meta_validation → 其余指标 → 输出`
   新增模块 `pipeline/timing.py` / `pipeline/meta_validation.py`。
   **每次覆盖都必须写入 `warnings` 数组与 `capability_report.md`** —— 用户必须看到"系统改了什么、为什么改"。

   > ✅ **无循环依赖确认**：`Q_pelletloss` ← A14 ← 颗粒轨迹关联 ← `v_sink_max`（来自无鱼标定视频）与 `ROI.bottom_band`，**均不依赖 `pellet_type`**。故"用 A14 反查 `pellet_type`"不存在循环。

### 5.1 `v_sink_max` 的标定（A14 关联约束的物理前提）

A14 的颗粒关联可行条件为：
```
max_displacement = v_sink_max × Δt  <  association_radius
```

**⚠️ `v_sink_max` 不得硬编码。** 不同饲料（浮性 / 缓沉 / 沉性）、不同粒径、不同水温下沉降速度差异极大，写死一个数会让关联在另一批饲料上**静默失效**——这是最难排查的一类 bug。

**标定方法（复用"无鱼纯饲料"视频，见 §7 素材清单）：**
1. 在无鱼视频中跟踪若干颗粒，测其**竖直位移 / 时间** → 得 `v_sink_max`（取 **95 分位**，不用最大值，防异常值）。
2. 同时测得平均粒径（px）→ 建议 `association_radius` 取 **2–3 倍粒径**。
3. 反解可行采样间隔：`Δt_max = association_radius / v_sink_max`。**若 `Δt_max` 小于当前采样间隔 → A14 在该窗口不可用**，须显式声明并标 `partial_window`，**不得报错崩溃或静默跳过**。

> 📌 这是「非对称采样早期窗口必须密」的**物理依据**——早期间隔不该拍脑袋定 1 s，而应由 `Δt_max` 反推。若某批饲料算出的 `Δt_max = 0.4 s`，那 1 s 间隔仍然不够密，config 必须能调。

> **所有阈值必须随结果导出到 `run_config.yaml`。** 跨组比较时两份配置不一致 → **报告顶部必须告警"本对比使用了不同参数，结果不可直接比较"**。

### 6.1.1 ⚠️ 为什么没有 `trustworthy` 列（**v3 修订，原设计已废弃**）

> **原 v2 设计了一列布尔 `trustworthy`，已废弃。** 由架构师高见远指出。
>
> **废弃理由（这是本契约里最重要的一条设计教训）：**
> `trustworthy == True` 的真实含义是「**未检测到已知缺陷**」，但用户会读成「**这个数是准的**」。
> **这两者差别极大：没有检测到的缺陷 ≠ 已验证的准确度。** 本项目的任何一个指标**都没有真值对照机制，没有任何一个"被验证过"**。用一个名叫 `trustworthy` 的布尔值，等于对用户做了一个**我们兑现不了的承诺**。
> 而且这类误读**同样不可察觉**——用户信任了不该信任的数，不会有任何报错。**这正是我们一路在防的那类错误（静默的、不可察觉的）。**

**替代设计（保留 100% 的筛选功能，去掉虚假承诺）：**

| 列 | 内容 |
|---|---|
| `blocking_flags` | 命中的阻断 flag，`;` 分隔，可为空。**筛空值即得原 `trustworthy=True` 的效果，但理由与结论在同一行** |
| `blocking_flag_count` | 整数。数字比布尔更难被过度信任，且便于排序 |
| `flags` | 全部 flag（含非阻断），供专家复核 |

> **核心设计原则：筛选辅助列必须与其判定依据相邻。** 这样即使用户只按 `blocking_flags == ""` 过滤，理由也始终在视野内——**筛选这个动作无法把结论和依据分开**。功能完全一样，只是不再撒谎。

### 6.1.2 ⭐ `blocking_flags` 的精确定义（可直接实现）

**① 阻断清单（7 项，内容类）**

| # | flag | 触发条件 |
|---|---|---|
| 1 | `contains_non_feeding_loss` | `Q_pelletloss > 0.15` 或 `pellet_type == 'sinking'` |
| 2 | `denominator_suspect` | `Q_n0gap > 0.20` |
| 3 | `sedimentation_risk_unassessed` | `pellet_type == UNKNOWN` |
| 4 | `counting_unstable` | `N_p` 非单调上升段占比 > 10% |
| 5 | `unstable_baseline` | 基线变异系数 > 0.5 |
| 6 | `low_conf` | 该指标依赖的检测/跟踪质量低于门限 |
| 7 | **`degenerate`** | **几何退化**（如 B2-4 FIFFB 的质心重复率超阈值）—— 几何已破坏，数值无意义 |
| 8 | **`fish_count_confounded`** | `Q_overlap` 超阈值（**鱼体重叠 → 计数与点模式统计与因变量混淆**，见 §4.4） |

> **第 8 项为何必须阻断（架构师 v10 提出，PM 确认）**：
> **一致性理由** —— 第 2 项 `denominator_suspect` 阻断的是**颗粒计数**与因变量混淆；若不同时阻断**鱼数**混淆，就会出现"颗粒侧严格、鱼数侧宽松"的不一致，而 **`P_fz` 与 RP（P0 主指标）恰恰建立在鱼数之上**，颗粒侧再严也救不回来。
> **性质理由** —— 难点 #2（鱼体重叠）是"精度不够"，**只需降级**；本条是"**误差幅度依赖于被测变量**"，**会伪造出组间差异**，必须阻断。
>
> ⚠️ **但必须正视它的代价**：阻断后，**在高聚集（即高诱食性）场景下 RP 将不可用** —— 而那正是我们最想测量的场景。
> **这恰恰反向证明了 §7.1「鱼数纳入真值对照」不是可选项而是必需品**：没有真值，我们就永远无法知道高聚集时的 RP 误差有多大，也就永远无法放宽这条阻断。**阻断与真值对照是配套的两半。**

**② 状态伪 flag（关键，防止漏筛）**

> **`blocking_flags` 在 `status != 'ok'` 时，必须额外包含一项 `status:<值>`**（如 `status:degraded`、`status:censored`）。

这样设计有三个好处，一次性解决三个问题：
- **单一列即可完成筛选**：`blocking_flags == ""` 等价于 `status=='ok'` 且无阻断 flag，用户不需要记住"还要另看 status 列"。
- **自动解决排序陷阱**：非 ok 的指标 `blocking_flag_count` 恒 ≥ 1，**不会被排序到最前面伪装成"最干净"**。
- **`uncalibrated`（B1-3 傅里叶未标定）等非阻断 flag 也能被正确拦截**——因为它必然伴随 `status='degraded'`，从而通过伪 flag 进入 `blocking_flags`。

**③ 空值纪律（延续本契约一贯原则）**
- `blocking_flag_count` 在 `status ∈ ('unavailable','censored')` 时为**空**，**不得为 0**。
- `blocking_flags` 无内容时为**空字符串**，不得写 `"none"` / `"-"` / `"OK"`（这些都会被 `== ""` 的筛选漏掉或误解）。

**④ 关于 `unnormalized`（px 未标定）——不进阻断清单，改在比较层拦截**
`unnormalized` 指标在**单次分析内**仍有意义（同一视频内可比较），不阻断。但它**不可跨视频比较**。因此：
> **`export/compare.py` 的新规则**：若参与比较的两个 run 的 `px_per_mm` 不一致，则**拒绝比较任何带 `unnormalized` 的指标**，并在对比报告中显式列出被拒绝的指标及原因。

**⑤ 配套：flag 术语表**
`capability_report.md`（人类可读报告）**必须包含一节「flag 术语表」**，把每个 flag 映射为一句用户能懂的中文解释。否则用户看到 `contains_non_feeding_loss` 无从判断该怎么办。
⚠️ **并须另出一份 `flag_glossary.csv`**（`flag_token, 中文名, 含义, 建议动作`）与 `metrics_summary.csv` **并列同目录**。**只看 CSV 的用户不会去打开 .md** —— 术语表必须在他们的动线上，否则等于没给。（本条由架构师补充，采纳。）

**⑥ ⚠️ 阻断清单必须版本化（本条由架构师指出，是 v2 方案的残留漏洞）**

> **风险**：阻断清单是**硬编码的产品决策，且直接决定用户看到哪些数是"干净的"**。我们锁了 26 个阈值，却没锁这个"决定什么叫干净"的清单——**同一类漏洞的残留，而且更隐蔽：阈值变了 `compare.py` 会报，清单变了它一声不响。**
>
> 一旦将来修订清单（如加入第 8 项），新旧两次运行的"阻断"含义就不同，**跨批比较照样失效**。

**要求：**
- `metrics_spec_version`（如 `ms-v1`）写入 `run_config.yaml`，并在 `metrics_summary.csv` 占一列。
- `compare.py` 除比对阈值外，**必须同时校验 `metrics_spec_version`，不一致即拒绝比较。**

**关于单版本 vs 双版本的建议（PM 提议，供架构师定夺）：**
建议**只用一个 `metrics_spec_version`**，而不是单独设 `blocking_flags_version`。理由：
1. 阻断清单与指标定义**在实践中一起变**（新增一个 flag 通常伴随某个指标的定义调整）；
2. **版本项越少越不容易被漏掉** —— 每多一个版本号，就多一处"改了代码忘了 bump"的风险；
3. 两种不一致的**补救方式完全相同**（见下），细分版本没有带来不同的处理动作。

**`compare.py` 的拒绝规则（两条）：**

| 触发条件 | 行为 |
|---|---|
| 两个 run 的 `px_per_mm` 不一致 | 拒绝比较任何带 `unnormalized` 的指标，并列出被拒指标及原因 |
| 两个 run 的 `metrics_spec_version` 不一致 | **拒绝整份比较**并告警 |

> 💡 **关于"拒绝整份比较"是否过严**：我认为不过严，因为**补救成本极低**——重跑一段视频在本机约 4 秒。所以在任何"不可比"场景下，正确做法都是**重跑对齐**，而不是让用户带着警告继续。**因此拒绝的报错信息必须写明这一点**（"请用当前版本重新分析 X 与 Y，各约需 4 秒"），把用户引向成本最低的出路，而不是让他卡住。

### 6.1.3 🔴 schema 纪律：每一列必须声明消费方（本条由架构师 v11 提出，PM 采纳并自查）

> **共同问题**：schema 里加了一列，但**没人定义"这一列该被谁、在什么时机消费"**。本项目已出现四次：
>
> | 列 | 问题 | 认领 |
> |---|---|---|
> | `window_s` | 有数据，compare.py 无规则 | PM |
> | `blocking_flag_count` | 有列，排序陷阱未处理 | 架构师 |
> | `ci_low`/`ci_high` | 有占位，无统计机制 | 现状 |
> | **`confidence`** | 有列（0–1 浮点），**从未定义语义，也无任何消费方** | **PM（本次自查发现）** |
>
> **纪律：新增任何一列时，必须同时声明它的消费方（哪个模块 / 哪类用户）与消费时机。没有消费方的列不进 schema —— 它只会让 CSV 变宽，不会让结论变可靠。**

**据此移除 `confidence` 列**（schema 净列数不变，因同时新增 `inferentially_valid`）。理由：
- 它**没有明确语义**（是检测置信度？指标置信度？）
- 它**没有消费方** —— 判断一个指标能不能用，已有 `status` + `blocking_flags` + `quality` 三者完整覆盖
- 一个语义模糊的 0–1 数字，风险与 `trustworthy` 同构：**用户会把它读成"可信度"，而我们从未定义它**

> 📌 这已是本项目第二次因同一原因删掉一个 0–1 的"可信度"字段。**教训：凡是形如"可信度/置信度"的标量，若无法给出明确定义与消费方，一律不进 schema。**

### 6.1.4 ⭐ `inferentially_valid`：跨组统计推断可用性（正交于 P0/P1/P2 优先级）

> **这是两个不同的轴，不应混为一谈**（回应架构师 v11"是否上调 B1 优先级"）：
> - **P0/P1/P2** 回答"**这个指标是否直接回答用户的问题**"
> - **`inferentially_valid`** 回答"**这个指标能否用于跨组统计推断**"
>
> **上调 B1 的 P0 优先级是错误的** —— B1 测的是活跃度，而**活跃 ≠ 摄食**（鱼可能因惊吓而活跃），它比 A 组（吃了多少、多快）与 B2 组 RP（来了多少鱼）更间接。
>
> **正确做法：新增一个正交标签**，让报告能同时表达"这个指标最直接"与"这个指标可做统计检验"。

| 取值 | 含义 | 判定 |
|---|---|---|
| `yes` | 可直接用于跨组统计推断 | **门控中立**（`Q_interf`/`Q_motion`/`Q_calib` 等外部条件） |
| `conditional` | 需满足条件后才可 | 门控非中立，或依赖需校验的量（如 A 组需 N₀ 双轨 + A14 校正通过） |
| `no` | 不得用于跨组统计推断 | 缺失具信息性（非中立门控触发关闭） |

**当前归类：**

| 指标 | `inferentially_valid` | 理由 |
|---|---|---|
| **B1-1 帧差能量 / B1-2 光流幅值 / B1-3 傅里叶频谱** | **`yes`** ⭐ | 门控均为外部环境量，误差均匀 |
| B1-4 混合熵 | `conditional` | `Q_fg` 非中立，修复后需复核 |
| **B1-5 群体游速** | ⚠️ **重归类为 C 组** | 依赖 `Q_track`，性质属个体级 |
| A 组（颗粒） | `conditional` | 需 `Q_n0gap` 通过 + A14 校正 |
| B2 组（聚集/RP） | `conditional` | 需 `Q_overlap` 未触发 `fish_count_confounded` |
| C 组（个体） | `no`（当由 `Q_track` 关闭时） | 缺失具信息性 |

> 💡 **这也给了"L0 靠不看鱼的全局特征"一个独立的第二条理由**（架构师 v11 洞察）：
> 不只是"不需要检测器就能跑"，而是**"它的门控是中立的，不会产出非随机缺失"**。

**另两点确认：**
- ✅ 同意 `status` 承载 `censored` 语义，不必单列 `censored`。
- ⚠️ 建议在 v2 再加 `ci_low` / `ci_high`（置信区间）。当前尚无统计推断机制，**本版不加，但列名先预留**，避免将来 schema 破坏性变更。

### 7.1 人工真值对照（`scripts/06_validate_against_groundtruth.py` 的输入规范）

真值对照是**唯一**能把"未检出缺陷"升级为"实测误差 = X"的途径（架构师 v6 决策 6）。工程侧已落地验证脚本，此处补充 **PM 侧的输入规范与五条纪律**。

**① 采样必须覆盖早期密集帧（🔴 强制）**

**🔴 真值必须同时包含「颗粒数」与「鱼数」两项**（**架构师 v10 提出，PM 强烈支持**）

> **为什么鱼数是必需的，而非锦上添花**：
> - **颗粒计数有 `N0_meta`（投喂量 ÷ 单颗均重）兜底**，而**鱼数没有任何独立的交叉校验手段**；
> - `P_fz`、**RP（P0 主指标）**、ANND、MDC、R90、FIFFB、D_peak **全部建立在鱼数之上**；
> - ⇒ **鱼数是整个指标体系里唯一一个「既无自检、又支撑着 P0 主指标」的量。**
>
> 人工数 5–10 帧的鱼数（**用同一批真值帧，顺手就能做**，成本几乎为零）即可补上这个洞。
> 且 §4.3 已把 `fish_count_confounded` 加入阻断清单 —— **阻断会在高聚集场景关掉 RP，而真值是唯一能让我们量化误差、进而放宽阻断的途径。阻断与真值对照是配套的两半。**

| 时段 | 帧数 | 说明 |
|---|---|---|
| **投喂后 0–10 s（颗粒最密集）** | **≥2–3 帧** | **强制项**。t≈0 时重叠最严重、召回最低，是系统性低估（难点 #9）的所在。**不采这些帧就测不出系统性偏差**，只采中后期会得到一个"看起来很准"而跳过了真正风险点的误差 |
| 投喂后 30 s / 60 s | 各 1–2 帧 | 中段 |
| **聚集最紧的时刻** | **≥2 帧** | **强制项（鱼数用）**。此时框重叠最严重，是 `fish_count_confounded` 与**衰减型偏差**（§4.6）的触发场景，**不采就测不出鱼数误差** |
| **剂量梯度：低端与高端各 ≥2 帧** | ≥4 帧 | **剂量梯度实验强制**（§4.6 ③）。**压缩差异最大的地方在剂量两端**，只采中间测不出衰减 |
| 接近吃完时 | 1–2 帧 | 尾段 |
| **合计** | **5–10 帧** | 同一批帧**同时数颗粒数与鱼数** |

**② 必须有人工计数协议，否则真值不是真值**（协议全文见 `docs/05` Q21）

| 情形 | 判定规则 |
|---|---|
| 计入范围 | 颗粒**质心**落在 `ROI.pellet_zone` 内即计入，含部分遮挡 |
| 粘连颗粒 | 可见分界线计 2，不可见计 1 |
| 边缘颗粒 | 压线按质心判定 |
| 疑似 | 计入并标记，供敏感性分析 |

**③ 五条纪律（防止"真值"成为新的欺骗源）**

1. **禁止基于 <30 帧的真值自动施加任何校正系数。** 只报告偏差，由用户决定是否采信。用小样本自动校正 = 用 5 个点的噪声修正全部数据，这正是我们一路在防的"兑现不了的承诺"，只是换了个包装叫"我们校准过"。
2. **必须报告"真值自身的噪声下限"。** ⭐ **PM 补充**：真值本身也有误差。若人工计数在密集帧上的评分者间差异就有 ±10%，那声称"我们 MAE = 8%"是无意义的——**无法区分自身误差与真值噪声**。因此建议**同一帧由两人独立计数**，验证报告须同时给出**评分者间一致性**与**我们的 MAE**。
3. 🔴 **实测误差 < 真值噪声下限时，必须输出"无法测量"，不得输出精度数字。**（**本条由架构师指出，是纪律 2 的缺口**）

   | 场景 | ❌ 错误结论 | ✅ 正确结论 |
   |---|---|---|
   | 未检出 flag | ~~这个数可信~~ | 未检出已知缺陷（≠ 已验证） |
   | **实测误差 < 真值噪声** | ~~**我们的误差 ≈ 0，很准**~~ | **误差落在真值噪声内，本方法无法测量** |

   > **这两行是同一句话的两种说法：没测出来 ≠ 没有。**
   > **这是同一陷阱第三次出现** —— ① 没检出 flag ≠ 可信；② 未版本化导致跨批不可比；③ 误差测不出 ≠ 误差为零。

   **强制输出模板**：
   > 「**本验证无法区分模型误差与真值噪声（实测误差 < 噪声下限）。要获得有效结论，需提高真值质量**（增加计数人数 / 更高分辨率人工复核 / 改用已知颗粒数的标定板）。」

   工程要求：`validation_report.md` 必须**并列展示**噪声下限与实测误差；当 `误差 < 噪声下限` 时，**自动输出上述结论并抑制任何精度数字的高亮展示**。
   **绝不能输出一个看着漂亮、实则无意义的精度数字**——它给用户虚假信心，且同样不可察觉。

4. **不得在 <30 帧时用"减噪声"的方式算修正后的误差**（如 `σ_model² ≈ MS(观测差) − σ_ref²`）。小样本下方差估计本身极不稳定，相减还可能得负值——**那会产出一个荒谬但看起来很专业的结果**。本版只**并列展示**，不做代数修正。（本条由架构师补充。）
5. **`Q_n0gap` 不是真值的替代品。** 它只能捕捉总量级粗大误差，**逐帧的系统性比例偏差它看不见**（稳定漏检 15% 时总量对得上，但中间每帧都偏低）。两者互补，都要做。

**验证报告应包含的统计量**：逐帧对照表 / **MAE · MAPE** / **有符号偏差 bias**（区分"稳定低估"与"随机抖动"，直接对应难点 #9）/ **评分者间一致性**（真值噪声下限）/ **误差 vs 噪声下限的判定结果** / Bland-Altman 一致性 / 与专家评分的相关系数。

> **展示纪律**：当判定为"无法测量"时，**所有精度数字降级为灰色次要信息**，结论区只显示「无法测量 + 改进建议」。

> **时机**：真值必须在**已知且可复现的时间点**上数。**视频归档后再补几乎无法对齐** —— 务必在正式采集数据前安排（见 `docs/05` Q21 + 素材 4）。

## 7. 单元测试建议（`tests/test_metrics.py`）

必测场景（工程师照此写用例）：

1. **N₀ 交叉校验**：`N0_det` 与 `N0_meta` 偏差 > 20% → 断言 `flags` 含 `denominator_suspect`。
2. **右删失**：构造一条从未降到 0.5N₀ 的曲线 → 断言 `T50.value is None and T50.censored is True`，**且不得为 0**。
3. **N₀ 系统性低估**：构造早期密集（漏检）→ 断言 `Q_n0gap` 能捕捉。
4. **非单调回补**：构造 N_p 回升段 > 10% → 断言 `counting_unstable=True`。
5. **基线缺失**：`BaselineStats=None` → 断言 `RP` 不输出且 `disabled_with_reason` 有记录。
6. **B1/B2 不可合并**：断言 `aggregator.py` 输出结构中 B1、B2 是两个独立键。
7. **沉降损失未校正**：`A14` 不可用 → 断言 T90/T100 的 `flags` **不含** 已校正标记，且含 `contains_non_feeding_loss`。
8. **降级开关**：人为设 `Q_track=0.3` → 断言整组 C 被关闭且在报告中显式列出。
9. **配置留档**：两次不同阈值的运行 → 断言 `run_config` 不同，且对比功能触发"参数不一致"告警。

### 7.1 第二类单测：**边界完整性**（测"有没有撒谎"，非"算得对不对"）

> 📌 由来（架构师 v8 推论，PM 采纳）：**在本项目里，"测试通过"不是有效的质量信号。单测能验证"算对了"，验证不了"意思对了"**——后者只能靠显式的边界传递。
> 因此单测应分两类：**数值正确性**（上面 9 条）+ **边界完整性**（下面这些）。**这类断言测的不是数值，是"有没有做出无法兑现的声明"。**

| # | 场景 | 断言 |
|---|---|---|
| B1 | A14 不可用时 | 断言**未**输出 `metadata_contradiction`，且输出 `sedimentation_risk_unverifiable`，且话术**不含**"实测" |
| B2 | 验证判定为"无法测量"时 | 断言精度数字被抑制高亮，结论区含"无法区分模型误差与真值噪声" |
| B3 | 用户元数据被覆盖时 | 断言 `warnings` 数组与 `capability_report.md` **都**记录了"改了什么、为什么改"（不能只写一处） |

| 7 | **新增**：早期间隔 1 s 是否足够密 | 应由 `Δt_max = association_radius / v_sink_max` **反推**而非拍脑袋（§5.1）。浮性料没问题；**沉性料可能需要 <1 s**，需在拿到 `v_sink_max` 实测值后回验 |
