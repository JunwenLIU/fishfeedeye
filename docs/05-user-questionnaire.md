## 一、🔴 阻塞项（7 条）

### Q1. 拍摄视角与机位
- [ ] 俯拍（相机在水面上方向下）
- [ ] 侧拍（相机在水面侧向）
- [ ] 其他：______
- [ ] 相机**固定不动**
- [ ] 相机会晃动/移动

> **为什么问**：固定相机才能用背景建模做颗粒检测与运动分析；机位类型还会自动开关部分指标（如"上层鱼占比"仅在侧拍下可用）。

### Q2. 拍摄条件
- 水体清澈度：□ 清澈 □ 中等 □ 浑浊
- 饲料颗粒在画面中大约多少像素：□ <10 px □ 10–30 px □ 30–80 px □ >80 px
- 是否有明显水面反光/波浪：□ 无 □ 轻微 □ 严重

> **为什么问**：决定是否需要切片推理（SAHI）、输入分辨率取多大、是否要做去雾预处理。颗粒 <10 px 时检测难度陡增，我们需要提前知道。

### Q3. 视频规格
- 分辨率：□ 720p □ 1080p □ 2K/4K □ 其他：______
- 帧率：□ 24/25/30 fps □ 50/60 fps □ 更高 □ 不确定
- **单次投喂过程的典型视频时长**：□ 3–5 min □ 5–10 min □ 10–20 min □ >20 min
- 单文件大致体积：□ <500 MB □ 0.5–2 GB □ >2 GB
- 🔴 **这段视频您打算怎么拍？**
  - [ ] **一个镜头从头录到底**（空镜头和投喂过程在同一个视频文件里）← 推荐
  - [ ] 先录一段空镜头，再录一段投喂，分成**两个文件**
  - [ ] 录制过程中有中断/暂停后续录
- 🔴 **拍摄时用的是哪种模式？**
  - [ ] **普通录像模式**（选这个）
  - [ ] 手机的**慢动作**模式
  - [ ] **延时摄影 / 缩时摄影**
  - [ ] 不确定（请看下面的说明对照确认）

> **为什么问**（后两问很关键，请务必看一下）：
> 我们的所有核心指标（T50/T90、残留率、摄食起止时刻、响应潜伏期）**全部建立在时间轴上**。时间轴出问题，**所有时间指标会一起错，而且不会报错**。
>
> **① 慢动作/延时**：视频内时间 ≠ 真实时间。慢动作 4 倍 → 所有时间指标被放大 4 倍。
> **⚠️ 这一类我们无法从视频文件内部检测**——慢动作文件自身完全自洽，只有您知道拍摄模式。
> **请务必使用正常拍摄模式**；若确实需要高帧率，请在相机设置里选「**高帧率录像**」而**不是**「慢动作」。
>
> **② 多段拼接**：拼接/续录会导致时间戳重置或跳变，**断裂点之后的时间指标会整体错位**。
> 我们会自动检测（时间轴不连续时告警并拒绝输出断裂后的时间指标），但**最优解是一镜到底**——投喂前空镜头与投喂过程录在同一个连续文件里即可。

> **为什么问（其余）**：决定采样策略与处理耗时（当前预估：20 分钟视频约 4 秒跑完，算力不是瓶颈）。

### Q4. 🔴 **本工具的使用范围（决定技术选型，最关键的一条）**
- [ ] **仅内部自用 / 科研自用**（不对外分发、不提供付费服务）
- [ ] 未来可能**作为商业产品分发**（出售许可或随设备交付）
- [ ] 未来可能**作为 SaaS / 云服务**提供给外部用户
- [ ] 尚不确定

> **为什么问（请务必理解）**：本项目主框架 Ultralytics 采用 **AGPL-3.0** 许可。
> - **仅自用**：完全没问题，AGPL 不触发任何义务。
> - **商业分发或 SaaS**：需要向 Ultralytics 购买 Enterprise License，否则存在合规风险。
> **这条必须在开发前确定**——后期更换框架的返工代价极大。
> 另：ShrimpFarming 数据集需签署许可协议后方可下载，能否使用同样取决于此项答案。

### Q5. 能否提供**投喂前的空镜头（基线期）**？
- [ ] 可以，每段视频投喂前有 30–60 秒空镜头
- [ ] 可以补拍
- [ ] 做不到

> **为什么问**：这是**所有归一化指标的分母**——相对偏好系数 RP、活跃度、聚集度、摄食起止时刻的判定阈值，全部依赖投喂前的基线统计。
> **没有基线，约一半指标只能输出绝对值，不同批次之间无法比较，横向对比直接失效。**
> 如果做不到请明确告知，我们会调整指标集，但**可输出的指标会显著减少**。

### Q6. 🔴 **饲料是浮性还是沉性？**
- [ ] 浮性（膨化浮料，投喂后漂浮于水面）
- [ ] 缓沉
- [ ] 沉性（投喂后下沉）
- [ ] 不确定

> **为什么问（这条比鱼种更关键）**：**在纯 2D 视频里，"颗粒被吃掉"与"颗粒沉底/漂出画面"本质上无法区分。**
> - 浮性料：颗粒停留在水面，消失基本等于被吃掉 → **清空时间类指标可信**。
> - 沉性料：颗粒会自行沉出观察区 → **清空时间会系统性偏快，可能得出完全相反的结论**。
> 若为沉性料，我们会改用"固定观察窗末残留率 RR"作为主指标，并把清空时间降为参考值、且必须与"非摄食损失率"并列展示。

### Q7. 能提供的**素材**（详见第三节）
- [ ] 3–5 段真实投喂全程视频（含投喂前基线）
- [ ] 1 段**无鱼纯饲料**视频 ← **强烈建议，一物三用**
- [ ] 投喂量与饲料规格元数据
- [ ] 以上暂时都提供不了（仅能口述需求）

> **为什么问**：素材决定我们是停留在"能跑"（规则法）还是能做到"能横向比较"（模型微调）。

## 二、🟠 高优先级（5 条，不影响启动但影响指标集）

### Q8. 目标鱼种与养殖模式
- 鱼种：______（淡水鱼 / 海水鱼 / 虾 / 其他）
- 养殖模式：□ 室内循环水（RAS） □ 池塘 □ 网箱 □ 水族箱/实验缸 □ 其他
- **单池个体数（可见密度）**：□ ≤15 □ 15–40 □ >40
- 摄食烈度：□ 抢食激烈、水花大 □ 温和、水花少 □ 不确定

> **为什么问**：
> ① 选预训练底座（不同公开数据集对应不同鱼种与场景）；
> ② **密度直接决定哪些指标能输出**——高密度下依赖个体检测的指标会被自动关闭；
> ③ 温和摄食的鱼水花少，光流/帧差信号弱，**活跃度灵敏度大幅下降**，此时我们会更依赖饲料颗粒曲线而非行为曲线。

### Q9. 愿意投入多少标注？
- [ ] 30–80 帧（约 1–2 小时）← 推荐起步量
- [ ] 300–1000 帧
- [ ] 3000 帧以上
- [ ] 希望完全不需要标注

> **为什么问**：决定走哪一档。**30–80 帧即可从"能跑"升级到"能横向比较"**（本机训练 10–20 分钟）。完全不标注也能用，但只能停留在规则法，指标集受限。

### Q10. 接受哪种"吃完"的判定口径？
- [ ] **固定观察窗末的残留率 RR**（推荐，默认 5 分钟窗口）
- [ ] T90（剩余 10% 的时刻）
- [ ] 颗粒数归零
- [ ] 不确定，听你们建议

> **为什么问**：**不建议用"颗粒数=0"**——尾部检测噪声大、总有颗粒卡在边角，且沉降与摄食不可分。
> **推荐 RR**：不依赖"清零"这个不稳定事件，跨组可比性最好。速度类指标建议用 **T50**（曲线最陡处，信噪比最高）。
> 注：阈值会做成可配置，报告里会写明用了哪个阈值——**不同阈值的结果不可直接比较**。

### Q11. 横向比较时，不同饲料的视频是否同一机位、同一光照？
- [ ] 是，同一机位同一时间段
- [ ] 同一机位，但不同时间（光照有变化）
- [ ] 机位或场景不同

> **为什么问**：决定是否必须做光照归一化，以及参数锁定的严格程度。**若条件不一致，我们会强制在对比报告中给出告警。**

### Q12. 是否需要实时处理？

### Q17. 你做这个工具，**最想回答的问题是什么？**（决定指标优先级与报告首页）
- [ ] **诱食性 / 引诱力** —— "鱼会不会被吸引过来？哪种料更招鱼？"
- [ ] **适口性 / 摄食速度** —— "鱼吃不吃、吃得多快、吃得多干净？"
- [ ] **投喂终点决策** —— "什么时候该停料？" （偏生产）
- [ ] **以上都要**，但最看重：______
- [ ] 不确定，先看你们能给出什么

> **为什么问**：这三个方向对应**完全不同的指标组合**，也决定报告首页展示什么：
> - 偏**诱食性** → 核心是响应潜伏期、投喂区鱼数占比 RP、聚集峰值（"来不来、多快来"）
> - 偏**适口性/摄食速度** → 核心是 T50/T90、峰值消耗速率、残留率 RR（"吃得多快、多干净"）
> - 偏**投喂终点** → 核心是摄食饱和时刻、摄食持续时长（"什么时候停"）
>
> 目前我们按"**诱食性 + 摄食速度并重**"设计，会同时输出上述指标。**但如果你有明确侧重，我们能把对应指标提到报告最前面并做重点解读**——指标全给反而容易让人抓不住重点。

### Q18. 你打算做怎样的**对比实验**？（决定统计方法）
- [ ] **两组对比**（对照 vs 一个实验组）
- [ ] **多组对比**（多个配方/多个处理，彼此独立）
- [ ] **剂量梯度**（同一添加剂设 3 个以上浓度，如 0% / 0.3% / 0.6% / 1.2%）
- [ ] 同一处理的**时间重复**（同一批鱼多次投喂，看稳定性）
- [ ] 以上组合：______

> **为什么问（⚠️ 剂量梯度那条尤其重要）**：
> **如果是剂量梯度，统计方法完全不同** —— 需要趋势检验 / 回归分析（看是否存在剂量-效应关系、求最适浓度），而不是两两 t 检验。文献里的诱食剂研究（如鳜诱食剂实验）就是靠"进入诱食剂区的相对次数 × 浓度"做**曲线回归**来求最佳添加浓度的。
> **这条会显著改变统计模块的设计，请务必说清楚。**

### Q19. 是否需要**统计推断**，还是只要数值对比？
- [ ] **只要数值对比**（看曲线、看数字即可）
- [ ] **需要显著性检验**（t 检验 / ANOVA + 多重比较，α=0.05）
- [ ] **需要效应量与置信区间**（Cohen's d、95% CI）← 若要写论文或正式报告，建议选这个
- [ ] 不确定

> **为什么问**：我们当前把置信区间（CI）列为**二期预留**。但**如果你要写论文或出正式研发报告，效应量与 CI 基本是刚需**——只有 p 值没有效应量，审稿人通常会要求补。
> 如果现在说需要，我们就把它提到第一版，成本不高；**等开发完再补，改动面会大得多。**

### Q20. 希望报告以什么形式交付？
- [ ] **Excel / CSV**（要拿去做二次分析、画自己的图）← 科研用户常见
- [ ] **PDF 报告**（可直接汇报、存档、附在申报材料里）
- [ ] **交互式网页**（可点开看曲线、翻看逐帧）
- [ ] **都要**（CSV + PDF）
- [ ] 不确定

> **为什么问**：决定我们在可视化与导出上的投入分配。CSV 我们一定会给；**PDF 报告需要额外做模板**（含元数据表头、方法说明、质量指标、flag 术语表），如果你的场景需要，我们会把它做成一版正式模板而不是简单截图。

### Q21. ⭐ 你打算**怎么验证我们给出的数是对的**？（这条对我们很重要）
- [ ] 有历史数据可以对照（如人工计数过颗粒数、人工评过摄食强度）
- [ ] **可以安排一次人工计数对照**（对 1 段视频人工数若干帧的颗粒数）
- [ ] 只能靠主观感觉判断合不合理
- [ ] 没想过 / 不确定

> **为什么问（请务必看一下这一条）**：
> **目前我们的任何一个指标都没有真值对照，所以我们无法向您承诺"这个数是准的"** —— 我们只能承诺"未检测到已知缺陷"。这是我们刻意的设计克制，不是保守。
>
> **但只要能拿到一次人工对照，情况就会完全不同**：
> - 您对 1 段视频人工数 **5–10 帧的颗粒数**，我们就能给出**颗粒计数的实测误差**（如 MAE = X 颗，误差 Y%）；
> - 您对若干段视频做一次**人工摄食强度评分**，我们就能算指标与人工判断的**相关系数**（文献中同类指标 CVFAI 达 r=0.92、FIFFB 达 r=0.94，我们可以给出本场景下的实测值）。
>
> **这是让工具从"能出数"变成"敢用这个数"的关键一步，成本很低但价值很高。** 建议在正式采集数据之前就安排上——**事后补做要比顺手做麻烦得多**（真值必须在已知且可复现的时间点上数，视频归档后再补几乎无法对齐）。

#### 📋 人工计数协议（**请照此执行，否则"真值"不是真值**）

如果没有统一协议，**评分者内/评分者间的变异会直接淹没测量本身**——我们花了整轮设计去防"数值骗人"，若最后用一个没有协议的"真值"去校准，等于在最关键的一环放水。

| 情形 | 判定规则 |
|---|---|
| 计入范围 | 颗粒**质心**落在投喂区（投饵框）内即计入，**含部分遮挡**的颗粒 |
| 粘连颗粒 | **能看到分界线**计 2 颗；看不到分界线计 1 颗 |
| 边缘颗粒 | 压在区域边界上的，按**质心**在哪一侧判定 |
| 模糊/疑似 | 计入，但在备注列标 `?`，便于事后敏感性分析 |

- **建议同一帧由两人独立计数**，不一致时复核取得一致（**并记录原始分歧**，理由见下）。
- 记录格式：`帧号（或时间点）, 计数人, 颗粒数, 备注`

> ⚠️ **补充一条容易被忽略的点（PM 补充）**：**真值本身也有误差。**
> 两人独立计数不仅是为了解决分歧，更是为了**量化"真值自身的噪声下限"**。如果人工计数在密集帧上的评分者间差异就有 ±10%，那么声称"我们的 MAE = 8%"是没有意义的——**我们无法区分自己的误差和真值本身的噪声**。
> 因此验证报告会同时给出：**评分者间一致性**（真值噪声下限）与**我们的 MAE**。只有当我们的误差显著大于前者时，"误差"这个说法才成立。

> 📌 **另请注意：投喂量元数据不能替代人工对照。**
> `理论颗粒数 = 投喂量 ÷ 单颗均重` 只能捕捉**总量级的粗大误差**；**逐帧的系统性比例偏差它看不见**（例如稳定漏检 15% 时总量对得上，但中间每帧都偏低）。**两者互补，都要做。**

## 三、📦 需要索取的素材

### 素材 1：真实投喂全程视频（3–5 段）— **必需**
| 要求 | 说明 |
|---|---|

### 素材 2：无鱼纯饲料视频（1 段）— **强烈建议，一物三用** ⭐
| 要求 | 说明 |
|---|---|
| 内容 | 池/缸中**无鱼**，只投放饲料，拍摄颗粒从投放到沉底/漂走的全过程 |
| 时长 | 60 秒左右即可 |

> **这一段视频同时解决三件事**：
> 1. 饲料颗粒检测器的**纯净正样本**（无鱼干扰，标注极快）
> 2. **非摄食损失率的标定基准**——无鱼时颗粒减少**只可能**是沉降或漂出，这是唯一能纯净测量该项损失的条件
> 3. **沉降速度与关联半径的标定源**——决定颗粒轨迹能否跨帧关联，进而决定清空时间指标能否被校正
>
> ⚠️ **沉降速度只能用无鱼视频标定**：有鱼视频测出的是"摄食+沉降"的混合速度，会让参数失效且极难排查。
> **建议只拍一段而不是三段** —— 三段视频若光照/机位/水温不同，标定出的参数根本不能用于正式视频，**采集条件一致比什么都重要**。

### 素材 3：投喂量与饲料规格元数据 — **成本极低，价值很高**
| 字段 | 用途 |
|---|---|
| 每次投喂量（克） | 与颗粒数做交叉校验 |
| 单颗饲料平均重量（毫克） | 推算理论颗粒总数 |
| 饲料粒径（毫米） | 关联半径标定 |
| 水温（摄氏度，可选） | 影响沉降速度与摄食活性 |

> **用途**：`理论颗粒数 = 投喂量 ÷ 单颗均重`，与视觉检测到的颗粒数做双轨校验。**两者偏差 >20% 时系统会告警提示可能漏检**——这是我们发现颗粒漏检最省事的手段之一。这些数据通常手头就有，成本几乎为零。

### 素材 4：人工计数对照（1 段视频的若干帧）— **可选，但强烈建议** ⭐

| 要求 | 说明 |
|---|---|
| 内容 | 任选 1 段真实视频，人工数出 **5–10 帧**画面中的**饲料颗粒数**与**鱼的数量**（**同一批帧，两项都数**） |
| **🔴 必采：颗粒最密集的早期帧** | **投喂后 0–10 s 内至少取 2–3 帧**（颗粒最多、重叠最严重的时候）。**这是必采项，不是可选项** —— 详见下方说明 |
| **🔴 必采：鱼群聚集最紧的时刻** | **至少 2 帧**。此时鱼体重叠最严重，是鱼数误差最大的场景 |
| **🔴 若做剂量梯度：剂量最低组与最高组各 ≥2 帧** | 压缩误差最大的地方在**剂量两端**，只采中间测不出偏差 |
| 其余建议覆盖 | 投喂后 30 s ／ 60 s ／ 接近吃完时 |
| 计数规则 | **严格按 Q21 的人工计数协议执行** |
| 记录 | `帧号（或时间点）, 计数人, 颗粒数, 鱼数, 备注` |

> ⭐ **为什么鱼数也要数（这点请特别注意）**：
> 颗粒计数有「投喂量 ÷ 单颗均重」可以交叉校验，**但鱼数没有任何独立的校验手段**——而**投喂区鱼数占比、相对偏好系数 RP（我们的核心指标之一）、聚集度指标全部建立在鱼数之上**。
> **鱼数是整套指标里唯一一个"既无法自检、又支撑着核心指标"的量。**
> 好消息是：**用同一批帧顺手数一下就行，成本几乎为零。**

> **为什么"早期密集帧"是必采项（这条最关键）**：
> 检测误差**不是均匀分布的**——**t≈0 时颗粒最密集、重叠最严重，检测器召回率恰恰在此时最低**。这意味着系统可能存在**系统性低估**（不只是随机抖动），而且这个偏差在各处理组之间还不一致（诱食性强的料被吃得快、重叠轻，召回高；弱的料堆积久、召回低），**会人为放大组间差异，可能得出方向错误的结论**。
> **不采早期密集帧，就测不出这个系统性偏差**——只采中后期会得到一个"看起来很准"的漂亮误差，而真正的风险点被跳过了。

> **用途：这是把"未检测到缺陷"升级为"实测误差 = X"的唯一途径。** 详见 Q21。
> 有了它，我们就能在报告里写"**本场景下颗粒计数 MAE = N 颗、有符号偏差 = ±M 颗**"，而不是只能说"未检出问题"。**对科研用途而言，这个差别很大。**

## 五、关于拍摄的建议（**请转达给拍摄人员**）

1. **相机必须固定**，不要手持、不要有云台自动巡检。
2. **不要加装亚克力/玻璃防水罩来隔绝反光。** 已有实测案例（Sensors 2025）表明：亚克力表面瑕疵会导致持续失焦模糊，拉开距离改善清晰度后反光噪声又会回来，**该方案已被原作者废弃**。
   ✅ **改用偏振镜（CPL）**，几十元成本，效果显著；同时**把投饵区放在画面中反光最小的位置**。
3. **尽量保持光照稳定**，避免阳光直射造成的时变阴影与水面高光。
4. **投饵区最好有固定的参照物**（如固定尺寸的投饵框、标定板），便于把像素换算成毫米。
5. **务必保留投喂前的空镜头**（见 Q5）。
6. 视频**不要做二次压缩**，尽量导出原始码流。
7. 🔴 **请使用正常拍摄模式，不要使用「慢动作」或「延时摄影」。** 这两者会让视频内时间 ≠ 真实时间，**所有时间指标（T50/T90、残留率、摄食起止时刻、响应潜伏期）会整体缩放，且系统无法自行检测**。
   ✅ 若需要高帧率（如沉性料建议的 60 fps），请在相机设置里选择「**高帧率录像**」而**不是**「慢动作」。
8. 🔴 **尽量一镜到底**——投喂前空镜头与投喂过程录在**同一个连续文件**里。多段录制后拼接会导致时间戳重置或跳变，断裂点之后的时间指标会错位（我们会检测并告警，但最优解是一镜到底）。
